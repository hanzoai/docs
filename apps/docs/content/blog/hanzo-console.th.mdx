# เปิดตัว Hanzo Console: การสังเกต LLM รวมไว้ที่เดียว

สร้างแอปพลิเคชัน LLM ในขนาดใหญ่คือการทำงานโดยมองไม่เห็น ส่งคำขอไปที่โมเดล ได้คำตอบกลับ แล้วหวังว่าทุกอย่างจะเดิน เมื่อไม่เดิน — ผลลัพธ์ผิด เวลาแฝงพุ่ง ต้นทุนระเบิด — คุณไม่เห็นว่าเพราะอะไร

วันนี้เราเปิด Hanzo Console: แพลตฟอร์มสังเกตการณ์รวมสำหรับแอปพลิเคชัน LLM

## Console ทำอะไร

Console ให้ภาพครบของการใช้ LLM ของคุณจากทุกผู้ให้บริการ:

**การตามรอย**: ทุกการเรียก LLM ถูกบันทึกพร้อมคำขอและคำตอบเต็ม เวลาแฝง จำนวนโทเค็น และต้นทุน ดูพรอมต์ตรงตัว ผลเติมเต็มตรงตัว และจังหวะเวลาในระดับโทเค็น

**การติดตามต้นทุน**: ต้นทุนตามเวลาจริงแยกตามโมเดล โครงการ ผู้ใช้ และกุญแจ API เห็นว่างบไปทางไหน แล้วปรับจากตรงนั้น

**การเฝ้าคุณภาพ**: ติดตามคุณภาพผลลัพธ์ตามเวลา จับการถดถอยก่อนถึงผู้ใช้ ทดสอบ A/B พรอมต์ด้วยนัยสำคัญทางสถิติ

**หลายผู้ให้บริการ**: แผงเดียวสำหรับ OpenAI, Anthropic, Together AI และผู้ให้บริการอื่นทุกเจ้าที่คุณใช้ เลิกปะรายงานจากพอร์ทัลเรียกเก็บเงินห้าแห่ง

## ภาษีของการเชื่อมระบบ

ผู้ให้บริการ LLM แต่ละรายมีแผงการใช้งานในรูปแบบใดรูปแบบหนึ่ง แต่ถ้าคุณใช้หลายราย — ซึ่งแอปพลิเคชันโปรดักชันส่วนใหญ่เป็นอย่างนั้น — คุณกำลังกระทบยอดรายงานจากห้าระบบที่มีห้าสคีมา

Console ไม่ผูกกับผู้ให้บริการ ใส่เครื่องมือวัดครั้งเดียว แล้วเห็นทั้งหมด

```python
from hanzo import Console

console = Console(api_key="your-key")

# Automatic tracing with context manager
with console.trace("user_query"):
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": user_input}]
    )
```

## การจัดการพรอมต์

Console มีทะเบียนพรอมต์ กำหนดรุ่นของพรอมต์ ติดตามว่ารุ่นใดถูกนำไปใช้ เปรียบเทียบประสิทธิภาพระหว่างรุ่น

ปัญหาของพรอมต์ในโค้ด: มันเก่า มันแยกสาขา และไม่มีใครรู้ว่ารุ่นใดกำลังรันในโปรดักชัน Console ทำให้พรอมต์เป็นสิ่งประดิษฐ์ที่ถูกจัดการในระดับแรก

## การคัดชุดข้อมูล

เปลี่ยนร่องรอยโปรดักชันเป็นชุดข้อมูลสำหรับประเมิน ทำเครื่องหมายผลลัพธ์ที่ดี ปักธงผลที่แย่ แล้วสร้างชุดความจริงอ้างอิงจากใช้งานจริงโดยตรง

เมื่อคุณพร้อมจะปรับละเอียดหรือเปลี่ยนผู้ให้บริการ คุณมีชุดข้อมูลที่สะท้อนทราฟฟิกโปรดักชันจริง — ไม่ใช่ตัวอย่างสังเคราะห์
