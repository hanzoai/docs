# Hanzo Console 공개: LLM 관측을 한곳으로

규모 있게 LLM 애플리케이션을 만드는 일은 계기 없이 나는 것이다. 모델에 요청을 보내고, 응답을 받고, 잘 되기를 바란다. 안 될 때 — 출력이 틀리고, 지연이 튀고, 비용이 터질 때 — 이유를 볼 수 없다.

오늘 Hanzo Console을 낸다. LLM 애플리케이션을 위한 통합 관측 플랫폼이다.

## Console이 하는 일

Console은 모든 제공자에 걸친 LLM 사용의 전체 그림을 준다.

**추적**: 모든 LLM 호출을 전체 요청과 응답, 지연, 토큰 수, 비용과 함께 기록한다. 프롬프트 그대로, 완성 그대로, 토큰 단위 타이밍을 본다.

**비용 추적**: 모델, 프로젝트, 사용자, API 키별 실시간 비용. 예산이 어디로 가는지 보고 그에 맞게 최적화한다.

**품질 감시**: 출력 품질을 시간축으로 따라간다. 회귀가 사용자에게 닿기 전에 잡는다. 통계적 유의성으로 프롬프트를 A/B 시험한다.

**여러 제공자**: OpenAI, Anthropic, Together AI, 그리고 쓰는 다른 모든 제공자를 한 대시보드에 둔다. 다섯 청구 포털의 보고서를 이어 붙이는 일을 멈춘다.

## 통합세

LLM 제공자는 각자 어떤 형태로든 사용량 대시보드를 낸다. 그러나 여러 제공자를 쓰면 — 대부분의 프로덕션 애플리케이션이 그렇다 — 스키마가 다른 다섯 시스템의 보고서를 맞춰야 한다.

Console은 제공자에 묶이지 않는다. 한 번 계측하면 전부가 보인다.

```python
from hanzo import Console

console = Console(api_key="your-key")

# Automatic tracing with context manager
with console.trace("user_query"):
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": user_input}]
    )
```

## 프롬프트 관리

Console에는 프롬프트 레지스트리가 있다. 프롬프트를 버전으로 관리하고, 어떤 버전이 배포됐는지 추적하고, 버전 간 성능을 비교한다.

코드 속 프롬프트의 문제: 낡고, 갈라지고, 프로덕션에서 어느 버전이 도는지 아무도 모른다. Console은 프롬프트를 일급 관리 산출물로 만든다.

## 데이터셋 선별

프로덕션 트레이스를 평가 데이터셋으로 바꾼다. 좋은 출력은 표시하고, 나쁜 출력은 깃발 세우고, 실제 사용에서 바로 기준 데이터셋을 만든다.

미세 조정이나 제공자 교체를 할 준비가 되면, 합성 예가 아니라 실제 프로덕션 트래픽을 반영한 데이터셋이 있다.
