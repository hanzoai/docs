# 자체 격자 암호: 처음부터 쓴 FHE

Microsoft에는 SEAL이 있다. Zama에는 tfhe-rs가 있다. IBM에는 HElib이 있다. 어느 것도 쓰지 않았다. 격자 프리미티브에서 Go로 완전 동형 암호 라이브러리를 직접 만들었다. C FFI 결합과 Rust 인터페이스가 붙는다.

NIH 증후군처럼 들린다. 그것이 아니었다.

## 왜 자체 FHE인가

완전 동형 암호는 암호문을 풀지 않고 그 위에서 계산하게 한다. 서버는 평문을 보지 않는다. 연산은 암호문 위에서 일어나고, 복호한 결과는 맞다. 암호화된 계산의 성배다.

있는 라이브러리는 이 문제를 특정한 방식으로, 특정한 용도로, 특정한 성능 맞바꾸기로 푼다. SEAL은 Microsoft의 클라우드 계산 모형에 맞춰져 있다. tfhe-rs는 불리언 회로 평가에 맞춰져 있다. HElib은 일괄 산술을 겨냥한다.

어느 것도 우리가 필요했던 것, 블록체인 위의 암호화된 데이터베이스 연산을 위해 설계되지 않았다. 체인 위의 저장, gas 비용, 블록체인 상태 데이터베이스 고유의 질의 패턴, 그 제약 안에서 도는 동형 연산이 필요했다.

## 구현

토대는 다항식 환 위의 RLWE(오차를 둔 환 학습)다. 환 구조가 동형 연산에 필요한 대수적 성질을 주고, 오차 항이 안전성 보장을 준다.

**다항식 산술**: 빠른 다항식 곱을 위한 NTT(수론 변환). 유한체에서의 FFT에 해당한다. 차수 N인 다항식 둘을 단순하게 곱하면 O(N^2)다. NTT는 그것을 O(N log N)으로 내린다. 우리 매개변수(N = 4096 또는 8192)에서는 쓸 수 있느냐 없느냐의 차이다.

**SIMD 최적화**: 다항식 계수는 SIMD 레인에 실린다. 암호문 하나가 병렬 슬롯에 수천 개의 평문 값을 부호화할 수 있다. 암호문 위의 동형 연산은 모든 슬롯에 동시에 작용한다. 이것은 GPU 병렬이 아니다. 스킴의 대수 구조에 구워진 데이터 병렬이다.

**부트스트래핑**: FHE의 근본 난제다. 동형 연산마다 암호문에 잡음이 더해진다. 충분한 횟수 뒤 잡음이 신호를 삼키고 복호가 실패한다. 부트스트래핑은 복호 함수를 동형으로 평가해 암호문을 갱신한다. 복호를 암호화하는 일이다. 우리 구현이 겨냥하는 것은 데이터베이스 연산에 필요한 최소 회로 깊이지, 범용 계산이 아니다.

## ZapDB: 암호화된 데이터베이스 저장

ZapDB는 FHE 라이브러리 위의 응용 계층이다. 암호화된 키-값 저장소이며, 거기서는:

- 값이 FHE 암호문으로 저장된다
- 질의가 암호문 위에서 실행된다
- 데이터베이스 서버는 평문 값을 보지 않는다
- 결과는 암호문으로 돌아오고, 키 보유자만 복호한다

블록체인 데이터베이스에서는 노드 운영자가 실제 상태 값을 한 번도 보지 않고 상태를 저장하고 질의할 수 있다. 프라이버시는 방침이 아니다. 수학적 보장이다.

질의 모형은 범용 데이터베이스보다 좁다. 동등 검사, 범위 질의, 산술 집계는 된다. 임의의 SQL은 안 된다. 이것은 FHE 스킴이 받치는 연산의 근본 한계이며, 빠진 기능이 아니다.

## C FFI와 Rust 바인딩

핵심 라이브러리는 Go다. 성능을 가르는 안쪽 루프 — NTT, 다항식 환원, 잡음 표본추출 — 는 C 구현을 갖고, Go가 CGO로 호출한다. SIMD 내장 함수는 C 코드에 있다.

Rust 바인딩은 C 인터페이스를 안전한 Rust 타입으로 감싼다. 그래서 Lux 노드 통합용 Go 라이브러리, 날것의 성능용 C 라이브러리, 스택의 나머지 중 Rust로 쓰인 것을 위한 Rust 바인딩이 갖춰진다.

```go
// Go interface
ct := fhe.Encrypt(pk, plaintext)
result := fhe.Add(ct1, ct2)
decrypted := fhe.Decrypt(sk, result)
// decrypted == plaintext1 + plaintext2
```

## 직접 쓰는 이유

남의 FHE 라이브러리를 쓰면 매개변수 선택, 잡음 예산 관리, RNG, 부채널 완화를 상대에게 맡긴다. 암호화된 데이터가 공개 블록체인 위의 금융 상태이고, 세상 모든 노드 운영자에게 보이는 응용에서는 공격면이 이론이 아니다.

처음부터 쓴다는 것은 매개변수 선택을 하나씩 이해한다는 뜻이다. N이 2048이 아니라 4096인 이유(안전 여유)를 안다. 계수 모듈러스가 소수 사슬로 짜인 이유(효율적인 모듈러 산술을 위한 RNS 표현)를 안다. 잡음 예산이 어디로 가고, 부트스트래핑 전에 몇 연산을 사슬로 이을 수 있는지를 안다.

이 이해는 라이브러리 문서에 없다. 체의 산술을 구현하고, 부트스트래핑 회로를 디버그하고, 잡음이 자라는 꼴을 실측하는 데서 온다. 코드가 이해 자체다.
