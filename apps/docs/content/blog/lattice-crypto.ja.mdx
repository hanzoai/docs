# 自前の格子暗号: ゼロから書いた FHE

Microsoft には SEAL がある。Zama には tfhe-rs がある。IBM には HElib がある。どれも使わなかった。格子のプリミティブから、Go で完全準同型暗号のライブラリを自分たちで書いた。C FFI の結合と Rust のインタフェース付きだ。

NIH 症候群に聞こえる。そうではなかった。

## なぜ自前の FHE か

完全準同型暗号は、暗号文のまま計算できる。サーバは平文を見ない。演算は暗号文の上で起き、復号した結果は正しい。暗号化された計算の聖杯だ。

既存のライブラリは、特定のやり方で、特定の用途に、特定の性能のトレードオフでこの問題を解く。SEAL は Microsoft のクラウド計算モデルに最適化されている。tfhe-rs はブール回路の評価に最適化されている。HElib はバッチ算術を狙う。

どれも、こちらが必要としたもの向けではなかった。ブロックチェーン上の、暗号化されたデータベース演算だ。チェーン上の保存、gas のコスト、ブロックチェーン状態データベースに固有の問い合わせパターン、その制約の中で動く準同型演算が要った。

## 実装

土台は多項式環の上の RLWE（誤差付き環学習）だ。環の構造が準同型演算に必要な代数的性質を与え、誤差項が安全性の保証を与える。

**多項式算術**: 高速な多項式乗算のための NTT（数論変換）。有限体における FFT に当たる。次数 N の多項式二つを素朴に掛けると O(N^2)。NTT はそれを O(N log N) にする。こちらのパラメータ（N = 4096 または 8192）では、使えるか使えないかの差になる。

**SIMD 最適化**: 多項式の係数は SIMD レーンに載る。一つの暗号文が、並列スロットに数千の平文値を符号化できる。暗号文への準同型演算は、全スロットに同時に効く。これは GPU の並列ではない。方式の代数構造に焼き付いたデータ並列だ。

**ブートストラップ**: FHE の根本的な難題だ。準同型演算のたびに暗号文へ雑音が足される。十分な回数のあと、雑音が信号を飲み、復号が失敗する。ブートストラップは復号関数を準同型に評価して暗号文を更新する。復号を暗号化することだ。こちらの実装が狙うのは、データベース演算に必要な最小の回路深さであり、汎用計算ではない。

## ZapDB: 暗号化されたデータベース格納

ZapDB は FHE ライブラリの上のアプリケーション層だ。暗号化されたキーバリューストアで、そこでは:

- 値は FHE 暗号文として格納される
- 問い合わせは暗号文の上で実行される
- データベースサーバは平文の値を見ない
- 結果は暗号文で返り、鍵の所持者だけが復号できる

ブロックチェーンのデータベースでは、ノード運用者は実際の状態値を一度も見ずに、状態を格納し問い合わせできる。プライバシーは方針ではない。数学的な保証だ。

問い合わせのモデルは汎用データベースより狭い。等価判定、範囲問い合わせ、算術の集約はできる。任意の SQL はできない。これは FHE 方式が支える演算の根本的な限界であり、欠けた機能ではない。

## C FFI と Rust バインディング

中核ライブラリは Go だ。性能が決まる内側のループ — NTT、多項式の還元、雑音のサンプリング — は C の実装を持ち、Go が CGO で呼ぶ。SIMD の組み込み関数は C のコードにある。

Rust のバインディングは C のインタフェースを安全な Rust 型で包む。これで Lux ノード統合用の Go ライブラリ、生の性能用の C ライブラリ、スタックの残りで Rust で書かれたもの向けの Rust バインディングが揃う。

```go
// Go interface
ct := fhe.Encrypt(pk, plaintext)
result := fhe.Add(ct1, ct2)
decrypted := fhe.Decrypt(sk, result)
// decrypted == plaintext1 + plaintext2
```

## 自前で書く意味

他人の FHE ライブラリを使うとき、パラメータの選択、雑音予算の管理、RNG、サイドチャネル対策を相手に預ける。暗号化されたデータが公開ブロックチェーン上の金融状態であり、世界中のノード運用者から見えるアプリケーションでは、攻撃面は理論の話ではない。

ゼロから書くとは、パラメータの選択を一つずつ理解することだ。N が 2048 ではなく 4096 である理由（安全余裕）を知っている。係数法が素数の鎖として組まれる理由（効率的な剰余算術のための RNS 表現）を知っている。雑音予算がどこへ行き、ブートストラップの前に何演算を鎖にできるかを知っている。

この理解はライブラリの文書にはない。体の算術を実装し、ブートストラップ回路をデバッグし、雑音の増え方を実測するところから来る。コードが理解そのものだ。
