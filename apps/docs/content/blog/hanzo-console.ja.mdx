# Hanzo Console を出す: LLM をひとつの画面で観測する

規模で LLM アプリケーションを作るのは、計器なしで飛ぶことだ。モデルにリクエストを送り、応答を受け取り、動いていることを願う。動かないとき — 出力が違う、レイテンシが跳ねる、費用が膨らむ — 理由が見えない。

今日、Hanzo Console を出す。LLM アプリケーションのための統合オブザーバビリティ基盤だ。

## Console がすること

Console は、全プロバイダにまたがる LLM 利用の全体像を渡す。

**トレース**: LLM 呼び出しのすべてを、リクエストとレスポンス全文、レイテンシ、トークン数、費用つきで記録する。プロンプトそのもの、補完そのもの、トークン単位のタイミングを見る。

**費用の追跡**: モデル、プロジェクト、ユーザー、API キーごとのリアルタイム費用。予算がどこへ行くかを見て、そこから最適化する。

**品質の監視**: 出力品質を時間軸で追う。退行が利用者に届く前に捕まえる。統計的有意性のある A/B でプロンプトを比べる。

**複数プロバイダ**: OpenAI、Anthropic、Together AI、そして使っている他のすべてのプロバイダを一つのダッシュボードに置く。五つの請求ポータルから報告書を継ぎ合わせるのをやめる。

## 統合の税

LLM プロバイダはそれぞれ、何らかの利用ダッシュボードを出している。しかし複数を使うなら — 本番アプリケーションの多くがそうだ — 五つのスキーマを持つ五つのシステムの報告書を突き合わせることになる。

Console はプロバイダに依存しない。一度計装すれば、すべてが見える。

```python
from hanzo import Console

console = Console(api_key="your-key")

# Automatic tracing with context manager
with console.trace("user_query"):
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": user_input}]
    )
```

## プロンプト管理

Console にはプロンプトレジストリがある。プロンプトを版管理し、どの版がデプロイされているかを追い、版ごとの性能を比べる。

コードの中のプロンプトの問題は、古くなり、分岐し、本番でどの版が走っているか誰も知らないことだ。Console はプロンプトを一級の管理対象にする。

## データセットの選別

本番トレースを評価データセットに変える。良い出力に印を付け、悪い出力に旗を立て、実利用から直接、基準となるデータセットを組む。

ファインチューンやプロバイダ変更の準備ができたとき、手元にあるのは合成例ではなく、実際の本番トラフィックを映したデータセットだ。

## いま使える

Console は [console.hanzo.ai](https://console.hanzo.ai) にある。無料枠は月 5 万トレース。エンタープライズ向けにセルフホストの配備をサポートする。
