# arcalabs: アセンブリ水準の証券エンジニアリング

st-contracts リポジトリは 2019 年 2 月 21 日、arcalabs の下に上がった。ERC-1400 を実装する証券トークン契約で、規制対応のために組んだ更新可能なプロキシの型を持つ。この文章は、その仕事が実際に何を含み、なぜアセンブリ水準まで降りる必要があったかについてだ。

## 証券トークンとは何か

ERC-20 トークンは、設計として許可を要しない。誰でも持てる、移せる、焼ける。それが要点だ。検閲耐性は機能であり、欠陥ではない。

証券トークンは違う。実在する資産の持分を表す。株式、債務、不動産、ファンド持分。証券法は移転に制限を課す。適格投資家の要件、管轄の限界、ロックアップ期間、開示義務。トークン契約がこれらの制限をプログラムで強制しなければ、名前の違う ERC-20 にすぎない。

ERC-1400 は、そのために現れた標準だ。`canTransfer` の検査で移転制限を入れた。移転が実行される前に、受取人がトークンを持てるかを契約が確かめる。規制対応の行為のための強制移転を加えた。裁判所は資産の移転を命じられる。契約はそれに応えねばならない。分割の管理も加えた。同じ証券の、性質の違うトランシェだ。

これはスマートコントラクト層の金融基盤だ。賭け金は DeFi プロトコルとは違う。トークン契約に欠陥があれば、実在の証券が危険にさらされる。正しさの基準はより高い。

## なぜ更新可能なプロキシか

証券は長生きする道具だ。2019 年に発行した証券トークンが、2024 年の移転制限規則を強制しなければならないことがある。EVM は、配備済みの契約コードを変えさせない。ロジックが配備時に凍っていれば、再配備する（すべての保有者、すべての残高、すべての状態を移すことになる）か、出荷した振る舞いのまま留まるかだ。

プロキシの型がこれを解く。アドレスが決して変わらないプロキシ契約と、実際の実装を持つロジック契約を配備する。保有者はプロキシとやりとりする。プロキシは呼び出しをロジック契約へ委譲する。ロジックを更新するときは、新しい実装を配備し、プロキシのポインタを更新する。

落とし穴がある。プロキシの型は微妙だ。委譲呼び出しは、ロジック契約のコードをプロキシのストレージ文脈で走らせる。ロジック契約のストレージ配置はプロキシの配置と両立しなければならない。さもなければ状態を壊す。更新の仕組み自体を守らねばならない。許可のない更新は壊滅的だ。

これを正しくやるには、コードを Solidity の水準で、それから EVM バイトコードの水準で追う必要があった。ここで必要な判断をコンパイラに任せることはできない。アセンブリの挿入は、ストレージスロット、呼び出しデータ、戻り値に何が起きているかを正確に確かめさせる。

## アセンブリ水準の EVM の仕事

EVM はスタックマシンだ。Solidity コンパイラは EVM バイトコードを出す。ほとんどのとき、コンパイラの出力は十分で、調べる必要はない。プロキシの型と、gas が効く経路では調べる。

Solidity のインラインアセンブリ（Yul の `assembly { }` ブロック）は、EVM の操作へ直接入る。ストレージの `sload` と `sstore`、呼び出しデータを読む `calldataload`、プロキシの転送のための `delegatecall`、戻り値を扱う `returndatacopy`。アセンブリで書いたプロキシの転送関数は、およそ 30 行で、どの呼び出しも正しく、gas の上乗せを最小にして扱う。

arcalabs が使った HPC（高性能計算）の枠組みは意図的だった。Ethereum の計算は高い。命令ごとに gas がかかる。アセンブリで最適化した熱い経路 — 移転の検証、プロキシの転送、イベントの発行 — は、Solidity の相当物より意味のある分だけ安い。現実の取引量では、gas の節約が効く。

## DEVxDAO とのつながり

DEVxDAO は、ブロックチェーン基盤の仕事に資金を出す、チェーン上の DAO だった。arcalabs は証券トークンの仕事で助成を受けた。ERC-1400 の基盤が、商業の仕事であるだけでなく、資金を出すに値する公共財だという正式な認識だ。

DAO の型は不完全だった（初期の DAO はどれも不完全だ）。しかし主張は正しかった。基盤の仕事には、明らかな商業モデルを持たず、助成を必要とするものがある。どのプロジェクトも使えるオープンソースの証券トークン契約は、その種の仕事だ。DEVxDAO とのつながりは、サイファーパンクの直感の制度的な形だった。金融基盤は公共であるべきだ。

## この水準で組むと何が分かるか

EVM のアセンブリを書くと、計算機はこちらの意図を知らないと分かる。書いたものを、正確に、解釈なしに実行する。間違ったものを書けば間違ったものを実行し、証券トークン契約には、配備から何年もあと、特定の条件でしか現れない欠陥がありうる。

これははっきりさせる。アセンブリを書く規律 — 命令がすべて明示で、暗黙のものがなく、各ビットに何が起きるかを正確に追える規律 — は、より高い抽象で書いていても、すべての金融基盤に欲しい規律だ。問いは「これは正しく見えるか」ではない。「これは正確に何を実行し、それは欲しいものか」だ。

その規律が、arcalabs の仕事を普通のスマートコントラクト開発から分ける。敵対的な条件の下での正しさ、寿命、規制への適応のために組んでいた。アセンブリ水準は、正しさを証明する場所であり、主張する場所ではない。
