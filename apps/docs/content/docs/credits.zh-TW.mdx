**讀完這一頁，你知道自己在花什麼、到哪裡去讀，以及
用盡之後會發生什麼。**

沒有席位授權，也沒有最低消費。你持有餘額，每一次按量呼叫
都按已公布的費率扣減，什麼都不送出的帳戶
一分錢也不收。

## 四個名詞

錢是四項能力，彼此不重疊。

| | 它回答什麼 | 位址 |
|---|---|---|
| **[定價](/docs/openapi/pricing)** | 花出去之前，一個單位值多少 | `/v1/pricing` |
| **[用量](/docs/openapi/usage)** | 你實際消耗了什麼 | `/v1/usage` |
| **[帳單](/docs/openapi/billing)** | 你的餘額、點數和發票 | `/v1/billing` |
| **[商務](/docs/openapi/commerce)** | 上面每一項都讀取的分類帳 | `/v1/commerce` |

按這個順序讀，整個經濟就是一句話：**定價**說出
費率，**用量**說出數量，**帳單**說出錢，而
**商務**是另外三項作為透鏡所對著的分類帳。

## 讀取餘額

```bash
hanzo billing balance
```

```bash
curl https://api.hanzo.ai/v1/billing/balance \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

點數在 `https://api.hanzo.ai/v1/billing/credits` 購買——或獲贈——
每一次扣減都是一筆分類帳分錄，所以餘額從不是某人
手工維護的數字。你消耗了什麼是另一次讀取，因為消耗
和錢是兩個不同的問題：

```bash
hanzo usage summary
```

## 兩道天花板，它們不是一回事

<Callout>
**餘額**是你擁有的。**配額**和**上限**是允許你
從中花掉的。把這三者搞混，是呼叫被拒絕而餘額看起來仍然健康的常見原因。
</Callout>

- **[配額](/docs/openapi/allowance)** — 呼叫方據以花費的一筆常設授予，
  位於 `/v1/allowance`。組織藉此把預算交給專案、金鑰或
  成員，而不交出全部餘額。
- **滾動上限** — 加在推論閘上的、針對人工智慧支出的尾隨視窗天花板。它連續重設，而不是在某個邊界重設：早於視窗的支出會掉出尾隨合計，因此沒有按月的懸崖，
  也沒有午夜歸零。它是閘上的一個鉤子，而不是一項獨立能力，
  所以沒有位址，也沒有頁面；上限本身是營運者編輯的
  平台旗標。

## 歸零時會發生什麼

按量呼叫會被拒絕。它在工作發生之前就在閘上被拒絕，
因此你永遠不會為一次本將失敗的呼叫付費——而且拒絕
會指出原因，而不是傳回一個籠統錯誤，這樣用戶端不必猜測就能區分
「點數用盡」和「金鑰錯誤」。不花錢的讀取仍然
應答：你始終可以查看一筆花不出去的餘額。

## 哪些呼叫要花錢

大多數不用。一項能力在程式碼旁邊宣告自己的價格——免費、固定，或
按量——免費的佔多數：列出專案、讀取
webhook 的投遞、取得自己的資料。按量計費的是
消耗真實資源的東西——推論詞元、沙箱秒數、一則外送簡訊、
一個被擷取的頁面。

每個能力頁面都給出自己的答案，[定價](/docs/pricing)
承載每個模型與工具的費率表。
