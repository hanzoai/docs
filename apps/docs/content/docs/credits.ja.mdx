**このページのあと、何を使っているか、どこで読むか、尽きると
何が起きるかを知っています。**

シート単位のライセンスも最低額もありません。残高を持ち、従量の呼び出しは
公開された単価でそれを減らし、何も送らないアカウントには
何も請求されません。

## 四つの名詞

お金は四つの機能であり、それらは重なりません。

| | 何に答えるか | アドレス |
|---|---|---|
| **[料金](/docs/openapi/pricing)** | 使う前に、1 単位がいくらか | `/v1/pricing` |
| **[利用状況](/docs/openapi/usage)** | 実際に消費したもの | `/v1/usage` |
| **[請求](/docs/openapi/billing)** | 残高、クレジット、請求書 | `/v1/billing` |
| **[コマース](/docs/openapi/commerce)** | 上のどれもが読む台帳 | `/v1/commerce` |

この順に読むと、経済全体は一文です。**料金**が単価を言い、
**利用状況**が数量を言い、**請求**がお金を言い、
**コマース**は残りの三つがレンズとして覗く台帳です。

## 残高を読む

```bash
hanzo billing balance
```

```bash
curl https://api.hanzo.ai/v1/billing/balance \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

クレジットは `https://api.hanzo.ai/v1/billing/credits` で購入する — または付与される —
そして減少のたびに台帳の記入になるので、残高は誰かが手で
維持した数字ではありません。消費したものは別の読み取りです。消費と
お金は別の問いだからです。

```bash
hanzo usage summary
```

## 二つの天井、そしてそれらは同じではない

<Callout>
**残高**は持っているものです。**手当**と**上限**は、そこから使ってよい
ものです。この三つを取り違えるのが、残高はまだ健全に見えるのに呼び出しが
拒否されるいつもの理由です。
</Callout>

- **[手当](/docs/openapi/allowance)** — 呼び出し元がそれに対して使う常設の付与で、
  `/v1/allowance` にあります。組織がプロジェクト、キー、または
  メンバーに、残高全体を渡さずに予算を渡す方法です。
- **移動上限** — 推論の門で適用される、AI 支出の追従窓の天井です。境界ではなく連続してリセットされます。窓より古い支出は追従合計から落ちるので、月次の崖も
  深夜のリセットもありません。それ自身の機能ではなく門のフックなので、
  アドレスもページもありません。上限そのものは、運用者が編集する
  プラットフォームの旗です。

## ゼロで起きること

従量の呼び出しは拒否されます。作業が起きる前に門で拒否されるので、
失敗するはずだった呼び出しの請求は発生しません — そして拒否は
汎用エラーを返すのではなく理由を名指しするので、クライアントは推測せずに
「クレジット切れ」と「不正なキー」を区別できます。費用のかからない読み取りは
答え続けます。使えない残高でも、いつでも確認できます。

## 費用がかかる呼び出し

ほとんどはかかりません。機能はコードのそばに価格を宣言します — 無料、定額、または
従量 — そして無料が多数です。プロジェクトの一覧、webhook の
配送の読み取り、自分のプロフィールの取得です。従量になるのは、
実資源を消費するものです — 推論トークン、サンドボックス秒、送信 SMS、
クロールしたページです。

各機能のページが自分の答えを述べ、[料金](/docs/pricing)
がすべてのモデルとツールの単価表を載せます。
