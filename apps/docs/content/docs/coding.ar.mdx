يشغّل `hanzo code` وكيل برمجة على المستودع الذي تقف فيه.
ثلاثة وكلاء مدعومة، وتسمية أحدها تعطيك ذلك الوكيل أو فشلًا واضحًا:
إنها منتجات منفصلة، وليست أبدًا أسماء بديلة لبعضها.

```bash
hanzo code                      # Hanzo Dev, the default
hanzo code claude               # Claude Code
hanzo code codex                # Codex
```

أعطه مهمة كوسيط **واحد**، بين علامتي اقتباس:

```bash
hanzo code "fix the failing test in api/users"
hanzo code claude "port this module to the new store"
```

## تسمية الوكيل

كل طريقة كتابة أدناه تُحسم في مكان واحد، فلا يمكن أن تتباعد:

| | موضعي | علم | صريح |
| --- | --- | --- | --- |
| Hanzo Dev | `hanzo code dev` | `hanzo code --dev` | `hanzo code --backend dev` |
| Claude Code | `hanzo code claude` | `hanzo code --claude` | `hanzo code --backend claude` |
| Codex | `hanzo code codex` | `hanzo code --codex` | `hanzo code --backend codex` |

`hanzo dev` اختصار من المستوى الأعلى لـ `hanzo code dev`. و`claude-code` و
`cc` كتابتان مقبولتان لـ `claude`.

تسميته مرتين تُرفض بدل أن تُحسم — `hanzo code claude --codex`
يطلب منك أن تسميه مرة واحدة.

## الموافقات

يوافق الوكيل على خطواته بنفسه افتراضيًا. مخرجان، بترتيب تصاعدي
لما يتنازلان عنه:

```bash
hanzo code --ask            # the backend asks before each step
hanzo code --no-sandbox     # bypass approvals AND drop the sandbox
```

`--safe` مرادف لـ `--ask`، وأي منهما يغلب `autoApprove` في
`~/.hanzo/settings.json`.

## `hanzo code` الآخر

`hanzo code context` و`hanzo code file` و`hanzo code index` شيء آخر يشارك الكلمة: إنها [API ذكاء الكود](/docs/openapi/code) — البحث والرموز عبر مستودعاتك المفهرسة،
لك وللوكلاء. لا تأخذ خلفية ولا تشغّل وكيلًا.

القاعدة هي الوسيط الأول: كلمة تسمّي خلفية تختارها، و
أي شيء آخر مهمة أو أمر فرعي.
