**หลังหน้านี้ คุณรู้ว่ากำลังใช้จ่ายอะไร อ่านได้ที่ไหน และ
เกิดอะไรขึ้นเมื่อหมด**

ไม่มีใบอนุญาตต่อที่นั่งและไม่มีขั้นต่ำ คุณถือยอดคงเหลือ ทุกการเรียกใช้ที่คิดตามปริมาณ
หักยอดนั้นในอัตราที่ประกาศไว้ และบัญชีที่ไม่ส่งอะไรก็ไม่ถูก
เรียกเก็บอะไร

## คำนามสี่คำ

เงินคือความสามารถสี่อย่าง และไม่ทับซ้อนกัน

| | ตอบอะไร | ที่อยู่ |
|---|---|---|
| **[ราคา](/docs/openapi/pricing)** | หนึ่งหน่วยราคาเท่าไร ก่อนที่คุณจะใช้จ่าย | `/v1/pricing` |
| **[การใช้งาน](/docs/openapi/usage)** | สิ่งที่คุณใช้ไปจริง | `/v1/usage` |
| **[การเรียกเก็บเงิน](/docs/openapi/billing)** | ยอดคงเหลือ เครดิต และใบแจ้งหนี้ของคุณ | `/v1/billing` |
| **[การค้า](/docs/openapi/commerce)** | สมุดบัญชีที่ทุกรายการด้านบนอ่าน | `/v1/commerce` |

อ่านตามลำดับนั้น แล้วเศรษฐกิจทั้งหมดคือประโยคเดียว: **ราคา** บอก
อัตรา **การใช้งาน** บอกปริมาณ **การเรียกเก็บเงิน** บอกเงิน และ
**การค้า** คือสมุดบัญชีที่อีกสามอย่างเป็นเลนส์มองเข้าไป

## การอ่านยอดคงเหลือ

```bash
hanzo billing balance
```

```bash
curl https://api.hanzo.ai/v1/billing/balance \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

เครดิตถูกซื้อ — หรือถูกมอบ — ที่ `https://api.hanzo.ai/v1/billing/credits`
และการหักทุกครั้งคือรายการในสมุดบัญชี ดังนั้นยอดคงเหลือไม่เคยเป็นตัวเลขที่ใครบางคน
ดูแลด้วยมือ สิ่งที่คุณใช้ไปเป็นการอ่านแยก เพราะการบริโภค
กับเงินเป็นคนละคำถาม:

```bash
hanzo usage summary
```

## เพดานสองแบบ และไม่ใช่สิ่งเดียวกัน

<Callout>
**ยอดคงเหลือ** คือสิ่งที่คุณมี **วงเงิน** และ **เพดาน** คือสิ่งที่คุณ
ได้รับอนุญาตให้ใช้จากยอดนั้น การปนสามอย่างนี้เป็นเหตุปกติที่การเรียกใช้
ถูกปฏิเสธทั้งที่ยอดยังดูปกติดี
</Callout>

- **[วงเงิน](/docs/openapi/allowance)** — เงินอุดหนุนถาวรที่ผู้เรียกใช้จ่าย
  ตัดกับมัน ที่ `/v1/allowance` นี่คือวิธีที่องค์กรมอบงบให้โครงการ กุญแจ หรือ
  สมาชิก โดยไม่มอบยอดทั้งหมด
- **เพดานเลื่อน** — เพดานหน้าต่างตามหลังบนค่าใช้จ่ายด้านปัญญาประดิษฐ์ ใช้ที่
  ประตูการอนุมาน มันรีเซ็ตต่อเนื่อง ไม่ใช่ที่ขอบเขต: ค่าใช้จ่ายที่เก่ากว่า
  หน้าต่างหลุดออกจากผลรวมตามหลัง จึงไม่มีหน้าผารายเดือน
  และไม่มีการรีเซ็ตตอนเที่ยงคืน มันเป็นตะขอที่ประตู ไม่ใช่ความสามารถ
  ของตัวเอง จึงไม่มีที่อยู่และไม่มีหน้า ตัวเพดานเองเป็น
  ธงของแพลตฟอร์มที่ผู้ปฏิบัติการแก้ไข

## เกิดอะไรขึ้นที่ศูนย์

การเรียกใช้ที่คิดตามปริมาณถูกปฏิเสธ มันถูกปฏิเสธที่ประตู ก่อนที่งานจะเกิดขึ้น
ดังนั้นคุณไม่ถูกเรียกเก็บเงินสำหรับการเรียกใช้ที่กำลังจะล้มเหลว — และการปฏิเสธ
ระบุเหตุผล แทนที่จะคืนข้อผิดพลาดทั่วไป เพื่อให้ไคลเอนต์แยก
«เครดิตหมด» จาก «กุญแจผิด» ได้โดยไม่เดา การอ่านที่ไม่เสียค่าใช้จ่ายยังคง
ตอบ: คุณตรวจยอดที่คุณใช้จ่ายไม่ได้เสมอ

## การเรียกใช้ใดมีค่าใช้จ่าย

ส่วนใหญ่ไม่มี ความสามารถประกาศราคาข้างโค้ดของมัน — ฟรี ราคาคงที่ หรือ
คิดตามปริมาณ — และรายการฟรีเป็นส่วนใหญ่: แสดงรายการโครงการ อ่าน
การส่งของเว็บฮุค ดึงโปรไฟล์ของตนเอง สิ่งที่คิดตามปริมาณคือสิ่งที่
ใช้ทรัพยากรจริง — โทเคนการอนุมาน วินาทีของแซนด์บ็อกซ์ SMS ขาออก 
หน้าที่ถูกเก็บ

ทุกหน้าของความสามารถบอกคำตอบของตนเอง และ[ราคา](/docs/pricing)
ถือตารางอัตราของทุกรุ่นและทุกเครื่องมือ

## ถัดไป

- **[ราคา](/docs/pricing)** — อัตรา ต่อล้านโทเคนและต่อการเรียกใช้
- **[การใช้งาน](/docs/openapi/usage)** — API การรายงาน
- **[การยืนยันตัวตน](/docs/api-keys)** — กุญแจจำกัดได้ที่รุ่นเดียว 
  โครงการเดียว หรือความสามารถเดียว ซึ่งเป็นอีกครึ่งหนึ่งของการควบคุมค่าใช้จ่าย
