`hanzo code` は、今いるリポジトリに対してコーディングエージェントを動かします。
三つが対応していて、名前を一つ指定するとそのエージェントか、はっきりした失敗が返ります。
別々の製品であり、互いの別名ではありません。

```bash
hanzo code                      # Hanzo Dev, the default
hanzo code claude               # Claude Code
hanzo code codex                # Codex
```

作業は引用符で囲んだ **一つの** 引数として渡します。

```bash
hanzo code "fix the failing test in api/users"
hanzo code claude "port this module to the new store"
```

## エージェントの名前

下の書き方はすべて一箇所で解決されるので、ずれません。

| | 位置引数 | フラグ | 明示 |
| --- | --- | --- | --- |
| Hanzo Dev | `hanzo code dev` | `hanzo code --dev` | `hanzo code --backend dev` |
| Claude Code | `hanzo code claude` | `hanzo code --claude` | `hanzo code --backend claude` |
| Codex | `hanzo code codex` | `hanzo code --codex` | `hanzo code --backend codex` |

`hanzo dev` は `hanzo code dev` の最上位の短縮形です。`claude-code` と
`cc` は `claude` として受け付ける書き方です。

二度名前を付けると解決せず拒否されます。`hanzo code claude --codex` は
一度だけ名付けるよう伝えます。

## 承認

エージェントは自分の手順を既定で自動承認します。手放すものが増える順に、出口は二つです。

```bash
hanzo code --ask            # the backend asks before each step
hanzo code --no-sandbox     # bypass approvals AND drop the sandbox
```

`--safe` は `--ask` の同義で、どちらも `~/.hanzo/settings.json` の
`autoApprove` に勝ちます。

## もう一つの `hanzo code`

`hanzo code context`、`hanzo code file`、`hanzo code index` は、同じ語を共有する別のものです。[コードインテリジェンス API](/docs/openapi/code) で、索引済みリポジトリを横断して検索とシンボルを引きます。
あなたのためにも、エージェントのためにもです。バックエンドは取らず、エージェントも動かしません。

規則は最初の引数です。バックエンドの名である語はそれを選び、
それ以外は作業かサブコマンドです。
