O Cloudflare Agents não tem um parâmetro próprio de URL base. A construção documentada é o cliente `openai` simples, construído dentro do Agent, com **`baseURL`** definido nele.

```bash
npm i agents openai
```

```ts
import { Agent } from "agents";
import { OpenAI } from "openai";

export class Researcher extends Agent {
  async onRequest(request: Request): Promise<Response> {
    const client = new OpenAI({
      apiKey: this.env.HANZO_API_KEY,
      baseURL: "https://api.hanzo.ai/v1",
    });

    const { readable, writable } = new TransformStream();
    const writer = writable.getWriter();
    const encoder = new TextEncoder();

    this.ctx.waitUntil(
      (async () => {
        const stream = await client.chat.completions.create({
          model: "zen5",
          messages: [{ role: "user", content: await request.text() }],
          stream: true,
        });
        for await (const part of stream) {
          writer.write(encoder.encode(part.choices[0]?.delta?.content || ""));
        }
        writer.close();
      })(),
    );

    return new Response(readable);
  }
}
```

Chega em `POST /v1/chat/completions`.

Ponha a chave num segredo de Worker — `wrangler secret put HANZO_API_KEY` — e ela chega em `this.env`. O streaming roda dentro de `ctx.waitUntil` para que o Worker não seja derrubado enquanto a resposta ainda está sendo escrita.

O outro caminho documentado é o AI SDK, que `AIChatAgent` e o modelo inicial já usam. Tudo na [página do Vercel AI SDK](/docs/guides/integrations/vercel-ai-sdk) vale sem mudança dentro de um Cloudflare Agent.

## MCP

MCP é um método no Agent, não uma biblioteca cliente. `addMcpServer` devolve um id e um `authUrl`; um `authUrl` não nulo significa que aquele servidor quer uma ida e volta OAuth, e o nosso não quer.

```ts
export class Researcher extends Agent {
  async onStart() {
    await this.addMcpServer("hanzo", "https://api.hanzo.ai/v1/mcp");
  }
}
```

Servidores conectados e suas ferramentas são legíveis a partir do estado MCP do Agent.
