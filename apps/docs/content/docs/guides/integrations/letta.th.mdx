Letta ไม่เปิดพารามิเตอร์ URL ฐานในระดับโค้ด ที่อยู่ถูกป้อนผ่านขั้นตอนตั้งค่า

เปิด **`/connect`** ในแอป Letta หรือรัน `letta connect` ใน CLI ซึ่งเปิดขั้นตอนเดียวกัน เพิ่มผู้ให้บริการกำหนดเองชนิด **API ที่เข้ากันได้กับ OpenAI** แล้วให้ URL ฐานและคีย์แก่เขา:

```
base URL:  https://api.hanzo.ai/v1
API key:   sk-...
```

จากนั้น `/model` เลือกโมเดล ลงที่ `POST /v1/chat/completions`

ข้อจำกัดสองข้อที่ Letta ระบุ และ Hanzo ทำได้ทั้งคู่ เอนด์พอยต์ต้องรองรับ chat completions และการเรียกเครื่องมือ — จึงเลือกโมเดลที่ระเบียน `GET /v1/models` บอกว่า `supports_tools` และเอเจนต์ที่โฮสต์บนคลาวด์ต้องมีเอนด์พอยต์ที่เข้าถึงได้จากอินเทอร์เน็ตสาธารณะ ไม่ใช่แค่ผ่าน localhost

Letta ส่ง `reasoning_effort` อย่างชัดเจนไปยังผู้ให้บริการที่เข้ากันได้กับ OpenAI ค่าหนึ่งใน `none`, `minimal`, `low`, `medium`, `high`, `xhigh` หรือ `max` และคาดว่าเอนด์พอยต์จะยอมรับ แมปใหม่ หรือปฏิเสธ

`LETTA_BASE_URL` เป็นคนละเรื่องและจะไม่ทำสิ่งนี้ มันคือที่อยู่ของเซิร์ฟเวอร์ Letta ที่โฮสต์เอง เช่น `http://localhost:8283` — ที่อยู่ของตัวเซิร์ฟเวอร์เอง ไม่เกี่ยวกับว่าการอนุมานไปที่ไหน

## MCP

เซิร์ฟเวอร์ไปอยู่ใน `mcpServers` ใน SDK เอเจนต์ของ Letta คีย์ตามชื่อ พร้อม `url` สำหรับตัวที่อยู่ไกล

```json
{
  "mcpServers": {
    "hanzo": {
      "url": "https://api.hanzo.ai/v1/mcp",
      "headers": { "Authorization": "Bearer sk-..." }
    }
  }
}
```

คีย์กลายเป็นเนมสเปซ: เครื่องมือมาถึงเป็น `mcp__hanzo__<tool>` การเชื่อมต่อเริ่มพร้อมกันเมื่อเซสชันเริ่มต้น และเซิร์ฟเวอร์ที่เข้าไม่ถึงหนึ่งตัวไม่กักตัวอื่นไว้
