لا يعرض Letta معامل عنوان URL أساسي على مستوى الشيفرة. يُدخل العنوان عبر تدفق إعداد.

افتح **`/connect`** في تطبيق Letta، أو شغّل `letta connect` في واجهة سطر الأوامر، وهو يفتح التدفق نفسه. أضف مزوّدًا مخصصًا من نوع **API متوافقة مع OpenAI**، وأعطه عنوان URL الأساسي والمفتاح:

```
base URL:  https://api.hanzo.ai/v1
API key:   sk-...
```

ثم يختار `/model` النموذج. يصل إلى `POST /v1/chat/completions`.

قيدان يذكرهما Letta، وHanzo يفي بهما معًا. يجب أن تدعم نقطة النهاية إكمالات المحادثة واستدعاء الأدوات — فاختر نموذجًا يقول سجلّه في `GET /v1/models` القيمة `supports_tools`. والوكيل المستضاف في السحابة يحتاج نقطة نهاية يمكن بلوغها من الإنترنت العام لا عبر localhost فحسب.

يرسل Letta قيمة `reasoning_effort` صريحة إلى المزوّدين المتوافقين مع OpenAI، واحدة من `none` أو `minimal` أو `low` أو `medium` أو `high` أو `xhigh` أو `max`، ويتوقع أن تقبلها نقطة النهاية أو تعيد تعيينها أو ترفضها.

`LETTA_BASE_URL` شيء آخر ولن يفعل هذا. هو عنوان خادم Letta مستضاف ذاتيًا، مثل `http://localhost:8283` — عنوان الخادم نفسه، بلا صلة بالمكان الذي يذهب إليه الاستدلال.

## MCP

تذهب الخوادم إلى `mcpServers` في SDK وكلاء Letta، بمفتاح حسب الاسم، ومع `url` للخادم البعيد.

```json
{
  "mcpServers": {
    "hanzo": {
      "url": "https://api.hanzo.ai/v1/mcp",
      "headers": { "Authorization": "Bearer sk-..." }
    }
  }
}
```

يصبح المفتاح فضاء الأسماء: تصل الأدوات بصيغة `mcp__hanzo__<tool>`. تبدأ الاتصالات معًا عند تهيئة الجلسة، وخادم واحد غير قابل للوصول لا يعطّل البقية.
