Letta не открывает параметр базового URL на уровне кода. Адрес вводится через поток настройки.

Откройте **`/connect`** в приложении Letta или выполните `letta connect` в CLI — откроется тот же поток. Добавьте своего провайдера типа **OpenAI-совместимый API** и дайте ему базовый URL и ключ:

```
base URL:  https://api.hanzo.ai/v1
API key:   sk-...
```

Затем `/model` выбирает модель. Попадает на `POST /v1/chat/completions`.

Два ограничения, которые называет Letta, и Hanzo удовлетворяет оба. Конечная точка должна поддерживать chat completions и вызов инструментов — выберите модель, в записи которой из `GET /v1/models` сказано `supports_tools`. А агенту в облаке нужна конечная точка, доступная из публичного интернета, а не только через localhost.

Letta посылает явное `reasoning_effort` OpenAI-совместимым провайдерам, одно из `none`, `minimal`, `low`, `medium`, `high`, `xhigh` или `max`, и ждёт, что конечная точка примет его, переназначит или отклонит.

`LETTA_BASE_URL` — это другое и этого не сделает. Это адрес самостоятельно размещённого сервера Letta, например `http://localhost:8283` — собственный адрес сервера, не связанный с тем, куда идёт инференс.

## MCP

Серверы кладутся в `mcpServers` в Letta Agent SDK, с ключом по имени и `url` для удалённого.

```json
{
  "mcpServers": {
    "hanzo": {
      "url": "https://api.hanzo.ai/v1/mcp",
      "headers": { "Authorization": "Bearer sk-..." }
    }
  }
}
```

Ключ становится пространством имён: инструменты приходят как `mcp__hanzo__<tool>`. Соединения стартуют одновременно при инициализации сессии, и один недоступный сервер не задерживает остальные.
