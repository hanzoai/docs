Letta कोड-स्तर का बेस-URL पैरामीटर नहीं दिखाता। पता एक कॉन्फ़िगरेशन प्रवाह से डाला जाता है।

Letta ऐप में **`/connect`** खोलें, या CLI में `letta connect` चलाएँ, जो वही प्रवाह खोलता है। प्रकार **OpenAI-संगत API** का कस्टम प्रदाता जोड़ें, और उसे बेस URL तथा कुंजी दें:

```
base URL:  https://api.hanzo.ai/v1
API key:   sk-...
```

फिर `/model` मॉडल चुनता है। `POST /v1/chat/completions` पर पहुँचता है।

दो बाधाएँ जो Letta बताता है, और Hanzo दोनों पूरी करता है। एंडपॉइंट को चैट कंप्लीशन और टूल कॉलिंग का समर्थन करना होगा — इसलिए ऐसा मॉडल चुनें जिसके `GET /v1/models` रिकॉर्ड में `supports_tools` लिखा हो। और क्लाउड-होस्टेड एजेंट को ऐसा एंडपॉइंट चाहिए जो सार्वजनिक इंटरनेट से पहुँचा जा सके, केवल localhost से नहीं।

Letta OpenAI-संगत प्रदाताओं को स्पष्ट `reasoning_effort` भेजता है, `none`, `minimal`, `low`, `medium`, `high`, `xhigh` या `max` में से एक, और अपेक्षा करता है कि एंडपॉइंट उसे स्वीकार करे, रीमैप करे या अस्वीकार करे।

`LETTA_BASE_URL` अलग चीज़ है और यह काम नहीं करेगी। यह स्वयं होस्ट किए Letta सर्वर का पता है, जैसे `http://localhost:8283` — सर्वर का अपना पता, इस बात से असंबंधित कि इनफेरेंस कहाँ जाता है।

## MCP

सर्वर Letta Agent SDK में `mcpServers` में जाते हैं, नाम से कुंजीबद्ध, दूरस्थ के लिए `url` के साथ।

```json
{
  "mcpServers": {
    "hanzo": {
      "url": "https://api.hanzo.ai/v1/mcp",
      "headers": { "Authorization": "Bearer sk-..." }
    }
  }
}
```

कुंजी नेमस्पेस बन जाती है: टूल `mcp__hanzo__<tool>` के रूप में आते हैं। सत्र आरंभ होते ही कनेक्शन साथ-साथ शुरू होते हैं, और एक अगम्य सर्वर बाकी को नहीं रोकता।
