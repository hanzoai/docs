У Cloudflare Agents нет собственного параметра базового URL. Документированная конструкция — обычный клиент `openai`, собранный внутри Agent, с заданным **`baseURL`**.

```bash
npm i agents openai
```

```ts
import { Agent } from "agents";
import { OpenAI } from "openai";

export class Researcher extends Agent {
  async onRequest(request: Request): Promise<Response> {
    const client = new OpenAI({
      apiKey: this.env.HANZO_API_KEY,
      baseURL: "https://api.hanzo.ai/v1",
    });

    const { readable, writable } = new TransformStream();
    const writer = writable.getWriter();
    const encoder = new TextEncoder();

    this.ctx.waitUntil(
      (async () => {
        const stream = await client.chat.completions.create({
          model: "zen5",
          messages: [{ role: "user", content: await request.text() }],
          stream: true,
        });
        for await (const part of stream) {
          writer.write(encoder.encode(part.choices[0]?.delta?.content || ""));
        }
        writer.close();
      })(),
    );

    return new Response(readable);
  }
}
```

Попадает на `POST /v1/chat/completions`.

Положите ключ в секрет Worker — `wrangler secret put HANZO_API_KEY` — и он приходит на `this.env`. Поток идёт внутри `ctx.waitUntil`, чтобы Worker не разобрали, пока ответ ещё пишется.

Другой документированный путь — AI SDK, которым `AIChatAgent` и стартовый шаблон уже пользуются. Всё со [страницы Vercel AI SDK](/docs/guides/integrations/vercel-ai-sdk) действует без изменений внутри Cloudflare Agent.

## MCP

MCP — это метод на Agent, а не клиентская библиотека. `addMcpServer` возвращает id и `authUrl`; ненулевой `authUrl` значит, что этот сервер хочет круговой путь OAuth, а наш — нет.

```ts
export class Researcher extends Agent {
  async onStart() {
    await this.addMcpServer("hanzo", "https://api.hanzo.ai/v1/mcp");
  }
}
```

Подключённые серверы и их инструменты читаются из MCP-состояния Agent.
