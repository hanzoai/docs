## 1. Boot the Full Local Runtime & OSS Cloud (10 Minutes)

Install the unified `hanzo` CLI, Dev coding agent, MCP server, and local model engine:

```bash
curl -fsSL https://hanzo.sh | sh
hanzo version
hanzo auth login
```

### Canonical CLI Lifecycle (3-Layer Model)

Hanzo separates the **local runtime** (microVM / native runtime, `k3s`, `containerd`, `hanzod`) from **platform & app workloads** (Hanzo Cloud, Engine, and your apps), so you can rebuild apps without restarting Kubernetes:

```bash
hanzo start                 # boot local runtime (VM, k3s, containerd)
hanzo up                    # start Hanzo Cloud & configured local workloads
hanzo ps                    # inspect Runtime, k3s, Cloud, hanzod & sandboxes
hanzo doctor                # verify local environment health
hanzo down                  # stop Cloud & apps while keeping k3s + image cache warm
hanzo stop                  # gracefully stop the local runtime and reclaim resources
```

### Zero-Kubernetes Loopback Mode (Fastest for Go / API Development)

If you want to iterate on the single static Cloud binary ([`hanzoai/cloud`](https://github.com/hanzoai/cloud)) and local model inference ([`hanzoai/engine`](https://github.com/hanzoai/engine)) directly on loopback:

```bash
# Terminal 1 — OSS Cloud core (encrypted SQLite /v1/base, /v1/tasks, /v1/kms, /mcp)
git clone https://github.com/hanzoai/cloud.git && cd cloud
make dev

# Terminal 2 — Local open-weight LLM & embeddings on :1234 (with built-in /ui chat)
hanzo pull zen-nano
hanzo engine serve zen-nano -- --host 127.0.0.1 -p 1234 --no-advertise

# Terminal 3 — Smoke-test both endpoints
curl -sS http://127.0.0.1:9090/healthz
curl -sS http://127.0.0.1:1234/v1/models
curl -sS -X POST http://127.0.0.1:8080/v1/base/collections/notes \
  -H "Content-Type: application/json" \
  -d '{"doc":{"title":"day-1-smoke"}}'
```

See [Self-Hosting & Air-Gapped](/docs/self-hosting) for adding local OIDC identity ([`hanzoai/iam`](https://github.com/hanzoai/iam)) and offline bundles.

## 2. Run the Full Agentic App Suite Locally

Once your local Cloud (`:8080`) and Engine (`:1234`) are running, connect the full client and agent ecosystem:

### Hanzo Dev Desktop & Hanzo Desktop
- **Install prebuilt binaries** (macOS, Windows, Linux): **[hanzo.ai/download](https://hanzo.ai/download)** — see [Desktop](/docs/apps/desktop) to point **Settings → Environments & Machines → Cloud API Endpoint** at `http://127.0.0.1:8080`.
- **Build standalone Hanzo Dev Desktop from source** ([`hanzoai/dev`](https://github.com/hanzoai/dev)):
  ```bash
  git clone https://github.com/hanzoai/dev.git && cd dev
  pnpm install
  pnpm run build:desktop
  ```

### Hanzo Mobile (Android & iOS)
Install the Android APK directly or build for iOS/Android over USB from [`hanzoai/mobile`](https://github.com/hanzoai/mobile) — full step-by-step instructions (including Linux-to-iOS USB sideloading) are in **[Mobile](/docs/apps/mobile)**.

### Hanzo Bot (Autonomous Resident Agents)
Run an always-on agent daemon connected to Slack, Discord, Telegram, WhatsApp, or iMessage backed by your local Engine and Cloud:

```bash
npm install -g @hanzo/bot
hanzo-bot onboard --install-daemon
```

Or build from source in [`hanzoai/bot`](https://github.com/hanzoai/bot).

### Hanzo Team & Hanzo Chat (Web Workspaces)
```bash
# Multi-model web chat pointed at your local engine
git clone https://github.com/hanzoai/chat.git && cd chat
pnpm install
VITE_HANZO_API=http://127.0.0.1:1234 pnpm dev

# Shared human + agent team workspace
git clone https://github.com/hanzoai/team.git && cd team
pnpm install && pnpm dev
```

### Hanzo MCP, Browser Extension & Progressive Skills
Wire unified tools and progressive skills into your coding agent so it never dumps huge docs into context:

```bash
# 1. Load Tier-0 progressive agent instructions (< 8 KB)
curl -fsSL https://hanzoskills.com/CLAUDE.md >> ~/.claude/CLAUDE.md

# 2. Attach Hanzo MCP (13 HIP-0300 unified tools over stdio)
claude mcp add --scope user hanzo -- npx -y hanzo mcp   # or: codex mcp add hanzo -- npx -y hanzo mcp

# 3. Unpack the Hanzo Browser Extension for live tab inspection & automation
mkdir -p ~/.hanzo/browser-extension && cd ~/.hanzo/browser-extension
URL=$(curl -fsSL https://api.github.com/repos/hanzoai/extension/releases/latest \
  | grep -oE 'https://[^"]*hanzo-ai-chrome[^"]*\.zip' | head -1)
curl -fsSL "$URL" -o ext.zip && unzip -oq ext.zip && rm ext.zip
```

Load `~/.hanzo/browser-extension` via `chrome://extensions` → **Developer mode** → **Load unpacked**. See [Skills, MCP & Desktop](/docs/skills) for Cursor, Windsurf, Gemini CLI, Copilot, and Antigravity configs.

## 3. Build Your First Hanzo App Into the `@hanzo/app` Siderail

Hanzo apps are **100% static client-side modules** (`@hanzo/mod`) that mount directly into the [`@hanzo/app`](https://github.com/hanzoai/app) host shell — inheriting the left siderail, IAM session, model picker, keyboard shortcuts, and `/v1` API access with zero custom backend servers.

### 1. Define Your App Mod Descriptor

Create a new mod package (or add a workspace mod inside [`hanzoai/app`](https://github.com/hanzoai/app)):

```tsx title="src/mods/cluster-pulse/index.tsx"
import type { Mod } from '@hanzo/mod';
import { Activity } from 'lucide-react';
import { ClusterPulsePane } from './Pane';
import { ClusterPulseBar } from './Bar';

export const clusterPulseMod: Mod = {
  id: 'cluster-pulse',
  title: 'Cluster Pulse',
  icon: Activity,
  path: '/cluster-pulse',
  Pane: ClusterPulsePane,
  Bar: ClusterPulseBar,
  capabilities: ['web', 'mcp'],
};

export default clusterPulseMod;
```

### 2. Wire Authenticated IAM, AI & Local Cloud State

```tsx title="src/mods/cluster-pulse/Pane.tsx"
import { useState } from 'react';
import { useIam } from '@hanzo/iam/react';
import { useAi } from '@hanzo/ai/react';
import { Button, YStack, Text } from '@hanzo/ui';

export function ClusterPulsePane() {
  const { org } = useIam();
  const { chat } = useAi();
  const [summary, setSummary] = useState<string>('');

  const inspectStack = async () => {
    const res = await chat({
      model: 'enso',
      messages: [
        {
          role: 'user',
          content: 'Check local runtime health and summarize active services and recent errors.',
        },
      ],
      tools: ['builtin:exec', 'builtin:fs'],
    });
    setSummary(String(res?.choices?.[0]?.message?.content ?? 'Done'));
  };

  return (
    <YStack flex={1} p="$4" gap="$3">
      <Text fontSize="$5" fontWeight="600">
        Cluster Pulse — {org?.name ?? 'Local Workspace'}
      </Text>
      <Button onPress={inspectStack}>Run Health Diagnostic</Button>
      {summary ? <Text>{summary}</Text> : null}
    </YStack>
  );
}
```

### 3. Mount Into the Siderail & Test Locally

1. Register `clusterPulseMod` in your host app's mod list so its icon (`Activity`) and route (`/cluster-pulse`) appear directly in the left siderail of `@hanzo/app`.
2. Start the shell against your local Cloud stack (`hanzo up` or `make dev` in `hanzoai/cloud`) and verify your mod renders in the siderail, reads the active IAM org, and executes `/v1` tool calls.
3. Optionally pair your mod with an **in-process TypeScript plugin** and a repo-local **`.hanzo/skills/<name>/SKILL.md`** so agents can drive your new app automatically.

Full contract, plugin runtime, and marketplace publishing details live in **[Building Apps & Mods](/docs/apps/mods)**.

## 4. Automate Tasks, Test Everything & Ship Clean PRs

Use the Hanzo CLI harness to accelerate debugging, testing, and refactoring across any cloned repository:

```bash
# Launch Hanzo Dev or any coding agent with Hanzo MCP attached
hanzo dev
hanzo --claude "add unit tests for edge cases in pkg/store"
hanzo --codex "reproduce and fix the race condition under go test -race"

# Run closed-loop CI/CD test repair with Hanzo Kata
kata run --suite tests/unit
```

### Definition of Done for Every PR
1. **Small, focused diff** branched cleanly off `main` in the target `github.com/hanzoai/<repo>`.
2. **All tests and linters pass locally** (`go test -race ./...`, `cargo test --locked && cargo clippy --all-targets -- -D warnings`, `pnpm test`, or `pytest`) — paste the exact command and output in your PR description.
3. **Fix friction as you find it**: if a `README.md`, `Makefile`, or docs page had a broken step, fix it in the same PR or open a companion PR on [`hanzoai/docs`](https://github.com/hanzoai/docs).
4. **Link your issue** (`Closes #<number>`) so bounty tracking and reviews stay connected.
