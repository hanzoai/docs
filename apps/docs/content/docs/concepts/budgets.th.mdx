**หลังจากหน้านี้ คุณจำกัดสิ่งที่เอเจนต์ใช้จ่ายได้ อ่านสิ่งที่มันใช้ไป และแยกการปฏิเสธงบประมาณจากความล้มเหลวของโมเดล**

## งบประมาณคืออะไร

ทุกการเรียกโมเดลและทุกการเรียกเครื่องมือที่มีราคาที่เอเจนต์ทำ **ถูกประเมินราคาก่อนทำ** — ขอบบนของสิ่งที่การเรียกอาจเสีย — และราคาประเมินนั้นถูกตรวจ ตามลำดับนี้ กับสี่สิ่ง:

1. **ยอดคงเหลือขององค์กรคุณ** — จ่ายได้เลยหรือไม่
2. **เพดานช่วงเวลาของเอเจนต์** — `cap_micro_usd` ลบสิ่งที่ช่วงนี้ใช้ไป
3. **เพดานงาน** — `max_task_micro_usd` ลบสิ่งที่การรันนี้ใช้ไป
4. **งบประมาณของเซสชัน** — `budget_micro_usd` ลบสิ่งที่เซสชันนี้ใช้ไป

อันใดอันหนึ่งปฏิเสธการเรียก ไม่มีธงและไม่มีทางอ้อม: การรันถึงโมเดลได้ทางประตูเท่านั้น

## เงินคือไมโครดอลลาร์จำนวนเต็ม

ทุกจำนวนเป็นจำนวนเต็มของไมโครดอลลาร์ ในฟิลด์ที่ลงท้าย
`_micro_usd` **1,000,000 คือหนึ่งดอลลาร์** ดังนั้น `11902000` คือ 11.902 ดอลลาร์ และ `250` คือหนึ่งในสี่สิบของเซนต์ การเรียกเสียเศษของเซนต์ เพดานที่เก็บเป็นเซนต์มองไม่เห็นหนึ่งนั้น

## ระบุงบประมาณ

ทั้งสามฟิลด์จำเป็นเมื่อคุณนิยามเอเจนต์

```bash
curl -X POST https://api.hanzo.ai/v1/agent \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "triage",
    "model": "zen-1",
    "instructions": "Triage inbound issues.",
    "cap_micro_usd": 20000000,
    "max_task_micro_usd": 500000,
    "period": "month"
  }'
```

เอเจนต์นั้นใช้ได้ **20 ดอลลาร์ต่อเดือน** และไม่มีการรันใดใช้เกิน **0.50 ดอลลาร์**

- `cap_micro_usd` ต้องเป็นบวก เพดานศูนย์หมายถึงไม่มีขีดและไม่มีบันทึก ซึ่งเป็นสถานะที่งบประมาณมีไว้เพื่อเอาออก
- `max_task_micro_usd` ต้องเป็นบวกและเกินเพดานไม่ได้
- `period` คือ `day`, `week` หรือ `month`

ช่วงเวลา **จัดแนวปฏิทินใน UTC**: `month` หมายถึงเดือนนั้น ไม่ใช่สามสิบวันจากการเรียกแรก และ `week` เริ่มวันจันทร์ หน้าต่างกลิ้งที่การเรียกแรกหลังจากมันพลิก และ `consumed_micro_usd` กลับเป็นศูนย์

## อ่านสิ่งที่มันใช้

```
GET /v1/agent/{ref}/spend
```

```json
{
  "cap_micro_usd": 20000000,
  "max_task_micro_usd": 500000,
  "period": "month",
  "consumed_micro_usd": 11902000,
  "remaining_micro_usd": 8098000,
  "by_component": { "model": 11431000, "computer": 402000, "tool": 69000 }
}
```

`by_component` แยกการใช้จ่ายสามทาง: **model** คือทุกการทำให้สมบูรณ์ที่เอเจนต์ซื้อ **computer** คือรันไทม์ที่มันอาศัย **tool** คือการเรียกเครื่องมือที่มีราคา ส่วนประกอบที่ไม่มีการใช้จ่าย **ขาดไป ไม่ใช่ศูนย์**

## การปฏิเสธหน้าตาเป็นอย่างไร

การทะลุตอบ `402` ด้วยรหัส `budget_exceeded`:

```json
{
  "error": {
    "code": "budget_exceeded",
    "message": "task budget exceeded: this call would cost up to 620000 micro-USD and 118000 remain",
    "event": "budget.exceeded",
    "scope": "task",
    "component": "model",
    "quote_micro_usd": 620000,
    "remaining_micro_usd": 118000
  }
}
```

`scope` ตั้งชื่อว่าเพดานใดปฏิเสธ — `agent`, `task` หรือ `session` — เพื่อให้คุณรู้ว่าจะยกเดือน การรัน หรือเซสชันนี้เซสชันเดียว

<Callout>
**เอเจนต์ถูกบอกในแถบ** ภายใต้เซสชัน เพย์โหลดเดียวกันถูกต่อเข้าสตรีมเหตุการณ์ของเซสชันเป็นเหตุการณ์สถานะจาก `budget` ดังนั้นเอเจนต์อ่านการปฏิเสธของตนขณะยังรัน และสรุปได้ — เขียนสิ่งที่มี พูดว่าทำไมหยุด — แทนที่จะล้มที่การเรียกที่ล้มเหลว
</Callout>

`budget_exceeded` ไม่ใช่ความล้มเหลวของโมเดล การเรียกที่โมเดลล้มเหลวถูกลองใหม่ การเรียกที่งบประมาณปฏิเสธไม่ถูก เพราะการลองใหม่จะปฏิเสธมันอีก

## ราคาประเมินเป็นขอบบน การชำระคือของจริง

ราคาประเมินผิดให้ใหญ่โดยตั้งใจ: พรอมต์อย่างที่จะถูกส่ง บวกการทำให้สมบูรณ์ที่ใหญ่ที่สุดที่คำขออนุญาต — `max_tokens` หรือ 4,096 เมื่อคำขอไม่ระบุ — ที่อัตราการอนุมานของแพลตฟอร์ม

เมื่อการเรียกเกิดขึ้นแล้ว สิ่งที่เกตเวย์ **รายงานจริง** ถูกชำระกับทุกยอดที่ราคาประเมินถูกตรวจ และส่วนต่างกลับสู่เพดาน การเรียกที่ล้มเหลวไม่เคยถูกชำระ จึงไม่เคยถูกเรียกเก็บ และช่องว่างของมันกลับมา

นี่คือเหตุที่เอเจนต์ถูกปฏิเสธทั้งที่ช่องว่างดูพอ: ประตูเทียบเพดานของการเรียกถัดไป ไม่ใช่ต้นทุนที่น่าจะเป็น

## งบประมาณของเซสชันเอง

เซสชันอาจถือเพดานของตน ใต้ของเอเจนต์:

```bash
curl -X POST https://api.hanzo.ai/v1/agent/sessions/$ID/budget \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"budget_micro_usd": 2000000}'
```

เซสชันที่ถึงงบของตน **ถูกหยุดชั่วคราว ไม่ล้มเหลว** — งานดำเนินต่อทันทีที่คุณยกเพดานหรือเอาออก สามกฎ:

- การแทนต้อง **มากกว่าอย่างเคร่งครัด** สิ่งที่เซสชันใช้ไป
- **การเอาออกเป็นทางเดียว**: `{"budget_micro_usd": null}` ถอดเพดานถาวร และเซสชันนั้นให้ใหม่ไม่ได้
- เซสชันที่ **สร้างโดยไม่มี** งบประมาณ ให้ภายหลังไม่ได้

แต่ละอย่างปฏิเสธด้วย `409` แทนที่จะทำอย่างอื่นอย่างเงียบ ๆ

## เอเจนต์ที่นิยามก่อนมีงบประมาณ

มันถือเพดานศูนย์และ **ไม่ถูกจำกัด** — การใช้จ่ายยังถูกสะสมและอ่านได้ที่ `/spend` และการอัปเดตให้เพดานแก่มัน การปฏิเสธทุกเอเจนต์ที่นิยามก่อนฟีเจอร์ออกจะเป็นการหยุดชะงัก ไม่ใช่นโยบาย
