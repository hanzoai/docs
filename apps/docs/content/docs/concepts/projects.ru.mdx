<Callout type="warn">
**«Проект» называет две вещи.** *Проект сайта* — это то, что вы разворачиваете.
*Проект IAM* — это область внутри организации. У них разные адреса,
разные жизненные циклы и разные владельцы. Спецификации держат их порознь; вам тоже стоит.

## Проект сайта — где живёт сайт

Идентификатор, под которым сборка разворачивается и отдаётся.

```bash
curl -X POST https://api.hanzo.ai/v1/projects \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"slug":"acme-marketing"}'
```

```bash
hanzo projects list
```

**slug** — несущая часть. Он становится сегментом ключа объектного хранилища,
публичным хостом `<slug>.hanzo.app` и идентификатором, к которому обращается каждый последующий вызов.
Он соответствует `^[a-z0-9]([a-z0-9-]{0,38}[a-z0-9])?$`, зарезервированные метки отклоняются,
и он уникален **в пределах организации** — тот же slug в чужой организации вас не касается.
Публичное имя хоста, напротив, уникально во всём мире и
достаётся тому, кто пришёл первым.

Создание также выделяет пространство данных и канонический git-репозиторий, оба по мере возможности.
Ответ — `201` в состоянии `draft`.

Его жизненный цикл — **выпуски**, а не окружения:

```
POST /v1/projects/{slug}/deploy
GET  /v1/projects/{slug}/releases
POST /v1/projects/{slug}/releases/{release}/activate
```

Каждое развёртывание — это выпуск, и любой выпуск можно снова сделать действующим, поэтому откат —
та же операция, что и продвижение вперёд. Собственные имена хостов проверяются по
`/v1/projects/{slug}/domains/{host}/verify`.

Публичная публикация бесплатна; `visibility: private` — платная возможность.

## Проект IAM — область внутри организации

Область, которую выбирают, когда работа разделена по продукту или клиенту,
а не по команде. Он создаётся и удаляется **только** по `/v1/iam/projects`
и едет в запросе как проверенный `X-Project-Id`.

```
GET /v1/iam/projects
```

Вы никогда не создаёте его где-то ещё. `/v1/platform/projects` — это *проекция*:
проект плюс то, что плоскость контейнеров положила под него, — и об этом сказано
прямо. Приложения живут под ним:

```
/v1/platform/projects/{project}/apps/{app}
/v1/platform/projects/{project}/apps/{app}/env
/v1/platform/projects/{project}/apps/{app}/preview
```

Ключ API можно ограничить одним проектом IAM. Так обычно не дают ключу предпродуктовой среды
задеть данные продакшена.

## Как их различить

| | Проект сайта | Проект IAM |
|---|---|---|
| **Что это** | развёрнутый сайт | область внутри организации |
| **Создаётся по** | `/v1/projects` | `/v1/iam/projects` |
| **Опознаётся по** | slug, уникальному в организации | id, который несётся как `X-Project-Id` |
| **Версионируется** | выпусками | ничем — это граница |
| **Возможность** | [проекты](/docs/openapi/projects) | [iam](/docs/openapi/iam) |

Практическое правило: **если вы разворачиваете байты, это проект сайта. Если вы
ограничиваете разрешения, это проект IAM.**
