**このページのあと、エージェントが使ってよい額を抑え、使った額を読み、予算の拒否をモデルの失敗と見分けられる。**

## 予算とは何か

エージェントが行うモデル呼び出しも、値段のあるツール呼び出しも、**行われる前に見積もられる** —
その呼び出しがかかりうる上限だ。その見積もりは、この順で四つのものに照らされる:

1. **組織の残高** — そもそも払えるか
2. **エージェントの期間上限** — `cap_micro_usd` から、この期間が使った分を引く
3. **タスクの天井** — `max_task_micro_usd` から、この実行が使った分を引く
4. **セッションの予算** — `budget_micro_usd` から、このセッションが使った分を引く

どれか一つが呼び出しを拒む。旗もなく、迂回もない。実行がモデルに届くのは門を通るときだけだ。

## 金は整数のマイクロ米ドル

金額はすべてマイクロ米ドルの整数で、フィールドの接尾は
`_micro_usd` だ。**1,000,000 が一ドル**なので、`11902000` は 11.902 ドル、`250` は
一セントの四十分の一だ。呼び出しはセントの端数しかかからない。セントで持った上限では
その一つが見えない。

## 予算を述べる

エージェントを定義するとき、三つのフィールドはすべて要る。

```bash
curl -X POST https://api.hanzo.ai/v1/agent \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "triage",
    "model": "zen-1",
    "instructions": "Triage inbound issues.",
    "cap_micro_usd": 20000000,
    "max_task_micro_usd": 500000,
    "period": "month"
  }'
```

このエージェントは **月に 20 ドル**使ってよく、一度の実行が **0.50 ドル**を超えて使うことはない。

- `cap_micro_usd` は正でなければならない。上限ゼロは制限もなく記録もないことで、予算が取り除くために存在する状態だ。
- `max_task_micro_usd` は正でなければならず、上限を超えてはならない。
- `period` は `day`、`week`、`month` だ。

期間は **UTC で暦に揃う**。`month` は月であって、最初の呼び出しから三十日ではない。`week` は月曜に始まる。窓は折り返したあとの最初の呼び出しで回り、`consumed_micro_usd` はゼロに戻る。

## 使った額を読む

```
GET /v1/agent/{ref}/spend
```

```json
{
  "cap_micro_usd": 20000000,
  "max_task_micro_usd": 500000,
  "period": "month",
  "consumed_micro_usd": 11902000,
  "remaining_micro_usd": 8098000,
  "by_component": { "model": 11431000, "computer": 402000, "tool": 69000 }
}
```

`by_component` は支出を三つに分ける。**model** はエージェントが買ったすべての補完、**computer** はそれが居た実行時、**tool** は値段のあるツール呼び出しだ。支出のない成分は **ゼロではなく、無い**。

## 拒否の姿

突破は `402` とコード `budget_exceeded` で答える:

```json
{
  "error": {
    "code": "budget_exceeded",
    "message": "task budget exceeded: this call would cost up to 620000 micro-USD and 118000 remain",
    "event": "budget.exceeded",
    "scope": "task",
    "component": "model",
    "quote_micro_usd": 620000,
    "remaining_micro_usd": 118000
  }
}
```

`scope` はどの天井が拒んだかを名指す — `agent`、`task`、`session` — 月を上げるのか、実行なのか、この一つのセッションなのかが分かる。

<Callout>
**エージェントには帯域内で告げられる。** セッションの下では同じ荷が、`budget` からの状態イベントとしてセッションのイベント流に足される。だからエージェントはまだ走っているあいだに自分の拒否を読み、締めくくれる — 持っているものを書き、なぜ止まったかを言う — 失敗した呼び出しで落ちる代わりに。
</Callout>

`budget_exceeded` はモデルの失敗ではない。モデルが失敗した呼び出しは再試行される。予算が拒んだ呼び出しはされない。再試行すればまた拒まれるからだ。

## 見積もりは上限、決済は実際

見積もりはわざと大きく外す。送られるとおりのプロンプトに、リクエストが許す最大の補完 — `max_tokens`、指名がなければ 4,096 — を、プラットフォームの推論レートで足す。

呼び出しが起きたあと、ゲートウェイが **実際に報告した** ものが、見積もりを照合したすべての集計に対して決済され、差は上限へ戻る。失敗した呼び出しは決済されないので請求されず、余裕は戻る。

だから、余裕が足りて見えるのにエージェントは拒まれうる。門は次の呼び出しの天井を比べるのであって、ありそうな費用ではない。

## セッション自身の予算

セッションは、エージェントの下に、自分の天井を持てる:

```bash
curl -X POST https://api.hanzo.ai/v1/agent/sessions/$ID/budget \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"budget_micro_usd": 2000000}'
```

自分の予算に達したセッションは **失敗ではなく一時停止** だ — 上限を上げるか外した瞬間に仕事は再開する。規則は三つ:

- 置き換えは、セッションが消費した額より **厳密に大きく** なければならない
- **外すのは一方通行**だ。`{"budget_micro_usd": null}` は上限を永久に外し、そのセッションに再び付けることはできない
- **予算なしで作られた**セッションに、あとから付けることはできない

どれも、黙って別のことをするのではなく `409` で拒む。

## 予算が存在する前に定義されたエージェント

上限ゼロを持ち、**抑えられていない** — 支出はそれでも集計され `/spend` で読め、更新が上限を与える。機能が出荷される前に定義されたすべてのエージェントを拒むのは、方針ではなく停止だ。
