**หลังจากหน้านี้ คุณรันโค้ดที่ไม่น่าเชื่อถือได้ และรู้แน่ชัดว่ามันหยุด
ทำให้คุณเสียเงินเมื่อใด**

## หนึ่งหน่วยพื้นฐาน

กระบะทรายคือพอดใต้เส้นแบ่งรันไทม์ มีชุดเครื่องมืออยู่ข้างในแล้ว
มีระบบไฟล์ของตน และมี**สัญญาเช่า**ที่จบมัน มีวัตถุเดียวและ
อายุเดียว — การรันไพธอนใช้แล้วทิ้งกับเซสชันเขียนโค้ดหลายชั่วโมงเป็น
สิ่งเดียวกันโดยมีขอบเขตต่างกัน

```bash
curl -X POST https://api.hanzo.ai/v1/sandbox/lease \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"class":"exec"}'
```

```bash
hanzo sandboxes list
```

การดำเนินการอื่นทุกอย่างกระทำต่อกระบะทรายที่การเรียกนั้นคืนมา

## สี่คลาส

เซตปิด ว่างหมายถึง `exec`

| คลาส | มันคืออะไร | ไดเรกทอรีทำงาน | มีชีวิต |
|---|---|---|---|
| `exec` | ใช้แล้วทิ้ง ไม่เก็บอะไร | `/mnt/data` | วินาทีถึงนาที |
| `dev` | เขียนโค้ด โดยดิสก์โปรเจกต์ถูกแนบ | `/work` | ชั่วโมง |
| `desktop` | `dev` บวกจอ | `/work` | ชั่วโมง |
| `android` | `desktop` บวกโทรศัพท์บนจอนั้น | `/work` | ชั่วโมง |

ทุกคลาสนอกจาก `exec` **ต้องการ**โปรเจกต์ และโปรเจกต์มี**กระบะทรายที่ยังมีชีวิต
ครั้งละหนึ่ง** — สัญญาเช่าที่สองบนโปรเจกต์ที่มีอยู่แล้วถูก
ปฏิเสธด้วยชื่อ แทนที่จะให้เครื่องที่สองอย่างเงียบ ๆ

คุณอาจ*ขอ*รันไทม์ (`gvisor` หรือ `kata-fc`) เจ้าของเป็นผู้ตัดสิน และ
คำตอบบอกสิ่งที่คุณได้จริง

## สองคำกริยาสำหรับจบ และความต่างสำคัญ

<Callout>
**`stop` จบงาน `end` จบทรัพยากร** การรันที่ผิดพลาดยัง
อ่านได้หลัง `stop` ซึ่งเป็นเหตุผลทั้งหมดที่พวกมันเป็นสองคำกริยา
</Callout>

นอกนั้น `ttlSec` จำกัดสัญญาเช่า และผู้เก็บเกี่ยววิ่งทุกนาที: มันจบ
สัญญาเช่าที่หมดอายุ และหลับกระบะทรายที่ว่างเกินหนึ่งชั่วโมง **ไม่มี
สระ** — กระบะทรายถูกสร้างเพื่อสัญญาเช่าและถูกลบตอนจบ และชื่อ
ไม่ถูกใช้ซ้ำ ดังนั้น id เก่าไม่มีวันถึงเครื่องของคนอื่น

## พอดทำอะไรได้

ไม่ใช่สิ่งที่คุณทำได้ ข้อมูลประจำตัวของคุณไม่เคยถึงพอด สัญญาเช่าได้รับ
โทเคนอายุสั้นหนึ่งอัน ได้มาโดยแลกโทเคนกับตัวตนของคุณ ทำตัวเป็น
ไคลเอนต์ `hanzo-sandbox` หมดอายุพร้อมสัญญาเช่า ไม่มีโทเคนรีเฟรช พอด
ไม่ถือข้อมูลประจำตัวคลัสเตอร์ของตนเอง

การแยกเป็นทางกายภาพ: ที่เก็บกระบะทรายคือหนึ่งไฟล์ต่อองค์กร

## exec: เซสชัน*คือ*กระบะทราย

[exec](/docs/openapi/exec) รันทั้งโปรแกรมในการเรียกครั้งเดียว ในสิบสาม
ภาษา — `py`, `js`, `ts`, `bash`, `r`, `php`, `go`, `rs`, `c`, `cpp`,
`java`, `d`, `f90`

```bash
curl -X POST https://api.hanzo.ai/v1/exec \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"language":"py","code":"print(6*7)"}'
```

มันไม่มีที่เก็บและไม่มีอายุของตนเอง — id เซสชันที่มันคืน*คือ*
id กระบะทราย การออกที่ไม่เป็นศูนย์คือ **`200` พร้อม stderr** ไม่ใช่สถานะข้อผิดพลาด:
การเรียกสำเร็จ โปรแกรมล้มเหลว และนั่นคือข้อเท็จจริงคนละอย่าง ส่ง
`session_id` เดิมอีกครั้งเพื่อเก็บระบบไฟล์ระหว่างการรัน

## ที่ที่มันพบเอเจนต์

`POST /v1/sandbox/run` เล่าเข้าเซสชันที่มีชื่อ และเอาต์พุตของมันถูกต่อ
เข้าบันทึกสดของเซสชันนั้น — บันทึกที่สตรีมเซสชัน[เอเจนต์](/docs/concepts/agents)
กำลังดูอยู่แล้ว นั่นคือรอยต่อระหว่างสองสิ่ง: กระบะทรายทำงาน
เซสชันคือบันทึกของงานนั้น
