## Один примитив

Песочница — это капсула под границей среды выполнения, с уже лежащей внутри цепочкой инструментов,
собственной файловой системой и **арендой**, которая её заканчивает. Один объект и одна
жизнь — одноразовый запуск Python и многочасовой сеанс программирования суть одно и то же
с разными пределами.

```bash
curl -X POST https://api.hanzo.ai/v1/sandbox/lease \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"class":"exec"}'
```

```bash
hanzo sandboxes list
```

Всякая другая операция действует на песочницу, которую возвращает этот вызов.

## Четыре класса

Замкнутое множество. Пусто значит `exec`.

| Класс | Что это | Рабочий каталог | Живёт |
|---|---|---|---|
| `exec` | одноразовая; ничего не хранит | `/mnt/data` | от секунд до минут |
| `dev` | программирование, с подключённым диском проекта | `/work` | часы |
| `desktop` | `dev` плюс экран | `/work` | часы |
| `android` | `desktop` плюс телефон на этом экране | `/work` | часы |

Каждый класс, кроме `exec`, **требует** проект, и у проекта **одна живая
песочница за раз** — вторая аренда поверх проекта, у которого она уже есть,
отклоняется по имени, а не молча выдаёт вам вторую машину.

Вы можете *запросить* среду выполнения (`gvisor` или `kata-fc`); решает владелец, и
ответ говорит, что вы на самом деле получили.

## Два глагола окончания, и разница важна

<Callout>
**`stop` заканчивает работу. `end` заканчивает ресурс.** Запуск, который пошёл не так, остаётся
читаемым после `stop`, и именно поэтому глаголов два.
</Callout>

Сверх того `ttlSec` ограничивает аренду, и жнец работает каждую минуту: он заканчивает
истёкшие аренды и усыпляет песочницы, простаивающие больше часа. **Пула
нет** — песочница создаётся под аренду и удаляется в её конце, а имена
никогда не используются снова, так что устаревший id никогда не дотянется до чужой машины.

## Что может капсула

Не то, что можете вы. Ваши учётные данные никогда не доходят до капсулы. Аренде выдают один
короткоживущий токен, полученный обменом токена на вашу личность, действующий как
клиент `hanzo-sandbox`, истекающий вместе с арендой, без токена обновления.
Капсула не несёт собственных учётных данных кластера.

Изоляция физическая: хранилище песочниц — один файл на организацию.

## exec: сеанс *и есть* песочница

[exec](/docs/openapi/exec) выполняет целую программу одним вызовом, на тринадцати
языках — `py`, `js`, `ts`, `bash`, `r`, `php`, `go`, `rs`, `c`, `cpp`,
`java`, `d`, `f90`.

```bash
curl -X POST https://api.hanzo.ai/v1/exec \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"language":"py","code":"print(6*7)"}'
```

У него нет собственного хранилища и собственной жизни — id сеанса, который он возвращает, *и есть*
id песочницы. Ненулевой выход — это **`200` со stderr**, а не статус ошибки:
вызов удался, программа провалилась, и это разные факты. Передайте тот же
`session_id` снова, чтобы сохранить файловую систему между запусками.

## Где это встречается с агентами

`POST /v1/sandbox/run` повествует в именованный сеанс, и его вывод дописывается
к живому журналу этого сеанса — тому, который поток сеанса [агента](/docs/concepts/agents)
уже смотрит. Это шов между ними: песочница делает
работу, сеанс — её запись.
