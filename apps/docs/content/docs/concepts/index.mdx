A catalogue this long can look like a pile of products that happen to share a login. It is not. Underneath it there are seven ideas, and almost every endpoint is one of them doing a particular job. Read these once. After that, a page you have never opened usually makes sense from its name and its address, which is a kinder way to learn an API than memorizing it.

The pages are short. The confusion they prevent is not. Worth the time.

## The one sentence

If you remember nothing else, remember this, and you can reconstruct the rest when you need it.

A **request** carries a credential. The edge turns that credential into an
**org** — the tenancy boundary every store is isolated on. Inside an org you
create **projects**, which scope work. Code runs in a **sandbox**, which is a
lease. An **agent** is a definition plus a **session** that can be steered and
replayed. What it may spend is its **budget**, checked before every call. What it
knows comes from **memory**. What runs without you asking is a **workflow**.

Everything else in the API is one of those seven, given a specific job. When a new page confuses you, come back and ask which of the seven it is. The answer is usually enough to start.
