**После этой страницы вы можете ограничить, сколько тратит агент, прочитать, сколько он потратил, и
отличить отказ бюджета от сбоя модели.**

## Что такое бюджет

Каждый вызов модели и каждый платный вызов инструмента, который делает агент, **оценивается до того,
как он сделан** — верхняя граница того, сколько вызов мог бы стоить, — и эта оценка
проверяется, в таком порядке, против четырёх вещей:

1. **баланс вашей организации** — можно ли это вообще оплатить
2. **потолок периода агента** — `cap_micro_usd` минус то, что потратил этот период
3. **потолок задачи** — `max_task_micro_usd` минус то, что потратил этот запуск
4. **бюджет сеанса** — `budget_micro_usd` минус то, что потратил этот сеанс

Любой из них отказывает вызову. Нет флага и нет обхода: запуск доходит
до модели только через ворота.

## Деньги — целые микродоллары

Каждая сумма — целое число микродолларов США, в поле с суффиксом
`_micro_usd`. **1 000 000 — это один доллар**, поэтому `11902000` — это 11,902 $, а `250` —
сороковая доля цента. Вызов стоит доли цента; потолок, хранимый в центах,
одной такой доли не увидел бы.

## Как задать бюджет

Все три поля обязательны, когда вы определяете агента.

```bash
curl -X POST https://api.hanzo.ai/v1/agent \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "triage",
    "model": "zen-1",
    "instructions": "Triage inbound issues.",
    "cap_micro_usd": 20000000,
    "max_task_micro_usd": 500000,
    "period": "month"
  }'
```

Этот агент может тратить **20 $ в месяц**, и ни один его запуск не может потратить больше
**0,50 $**.

- `cap_micro_usd` должен быть положительным. Потолок ноль значил бы ни предела, ни
  записи — именно то состояние, которое бюджет существует, чтобы убрать.
- `max_task_micro_usd` должен быть положительным и не может превысить потолок.
- `period` — это `day`, `week` или `month`.

Периоды **выровнены по календарю в UTC**: `month` значит месяц, а не тридцать
дней от первого вызова, и `week` начинается в понедельник. Окно перекатывается на
первом вызове после смены, и `consumed_micro_usd` возвращается к нулю.

## Читать, сколько он потратил

```
GET /v1/agent/{ref}/spend
```

```json
{
  "cap_micro_usd": 20000000,
  "max_task_micro_usd": 500000,
  "period": "month",
  "consumed_micro_usd": 11902000,
  "remaining_micro_usd": 8098000,
  "by_component": { "model": 11431000, "computer": 402000, "tool": 69000 }
}
```

`by_component` делит трату на три: **model** — каждое завершение, которое
агент купил, **computer** — среда выполнения, в которой он находился, **tool** — платный
вызов инструмента. Компонент без траты **отсутствует, а не равен нулю**.

## Как выглядит отказ

Пробой отвечает `402` с кодом `budget_exceeded`:

```json
{
  "error": {
    "code": "budget_exceeded",
    "message": "task budget exceeded: this call would cost up to 620000 micro-USD and 118000 remain",
    "event": "budget.exceeded",
    "scope": "task",
    "component": "model",
    "quote_micro_usd": 620000,
    "remaining_micro_usd": 118000
  }
}
```

`scope` называет, какой потолок отказал — `agent`, `task` или `session`, — чтобы вы знали,
поднимать месяц, запуск или этот один сеанс.

<Callout>
**Агенту говорят в полосе.** Под сеансом та же полезная нагрузка дописывается в
поток событий сеанса как событие статуса от `budget`, поэтому агент читает
собственный отказ, пока ещё работает, и может завершить — записать, что у него есть,
сказать, почему остановился, — вместо падения на неудачном вызове.
</Callout>

`budget_exceeded` — не сбой модели. Вызов, который провалила модель, повторяют; вызов,
который отказал бюджет, нет, потому что повтор отказал бы ему снова.

## Оценки — верхние границы, расчёт — фактический

Оценка нарочно завышает: запрос, каким он будет отправлен, плюс самое большое
завершение, которое разрешает запрос — `max_tokens`, или 4 096, когда запрос не называет
ни одного, — по тарифу вывода платформы.

Когда вызов произошёл, то, что шлюз **действительно сообщил**, рассчитывается
против каждого счёта, с которым сверялась оценка, и разница возвращается
к потолку. Неудачный вызов никогда не рассчитывается, поэтому не тарифицируется, и его
запас возвращается.

Поэтому агенту могут отказать при запасе, который выглядит достаточным: ворота
сравнивают потолок следующего вызова, а не его вероятную цену.

## Собственный бюджет сеанса

Сеанс может нести свой потолок, под потолком агента:

```bash
curl -X POST https://api.hanzo.ai/v1/agent/sessions/$ID/budget \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"budget_micro_usd": 2000000}'
```

Сеанс, достигший собственного бюджета, **ставится на паузу, а не помечается сбоем** — работа возобновляется
в тот момент, когда вы поднимаете потолок или снимаете его. Три правила:

- замена должна быть **строго больше** того, что сеанс потребил
- **снятие одностороннее**: `{"budget_micro_usd": null}` снимает потолок
  насовсем, и этому сеансу нельзя дать его снова
- сеансу, **созданному без** бюджета, нельзя дать его позже

Каждый из этих случаев отказывает с `409`, а не делает тихо что-то другое.

## Агент, определённый до того, как появились бюджеты

Он несёт потолок ноль и **не ограничен** — его трата всё равно суммируется и
читается по `/spend`, а обновление даёт ему потолок. Отказывать каждому агенту, определённому
до выхода функции, было бы простоем, а не политикой.
