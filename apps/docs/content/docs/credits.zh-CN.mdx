用尽之后会发生什么。**

没有席位许可，也没有最低消费。你持有余额，每一次按量调用
都按已公布的费率扣减，什么都不发送的账户
一分钱也不收。

## 四个名词

钱是四项能力，彼此不重叠。

| | 它回答什么 | 地址 |
|---|---|---|
| **[定价](/docs/openapi/pricing)** | 花出去之前，一个单位值多少 | `/v1/pricing` |
| **[用量](/docs/openapi/usage)** | 你实际消耗了什么 | `/v1/usage` |
| **[账单](/docs/openapi/billing)** | 你的余额、积分和发票 | `/v1/billing` |
| **[商务](/docs/openapi/commerce)** | 上面每一项都读取的分类账 | `/v1/commerce` |

按这个顺序读，整个经济就是一句话：**定价**说出
费率，**用量**说出数量，**账单**说出钱，而
**商务**是另外三项作为透镜所对着的分类账。

## 读取余额

```bash
hanzo billing balance
```

```bash
curl https://api.hanzo.ai/v1/billing/balance \
  -H "Authorization: Bearer $HANZO_API_KEY"
```

积分在 `https://api.hanzo.ai/v1/billing/credits` 购买——或获赠——
每一次扣减都是一条分类账分录，所以余额从不是某人
手工维护的数字。你消耗了什么是另一次读取，因为消耗
和钱是两个不同的问题：

```bash
hanzo usage summary
```

## 两道天花板，它们不是一回事

<Callout>
**余额**是你拥有的。**配额**和**上限**是允许你
从中花掉的。把这三者搞混，是调用被拒绝而余额看起来仍然健康的常见原因。
</Callout>

- **[配额](/docs/openapi/allowance)** — 调用方据以花费的一笔常设授予，
  位于 `/v1/allowance`。组织借此把预算交给项目、密钥或
  成员，而不交出全部余额。
- **滚动上限** — 加在推理门上的、针对人工智能支出的尾随窗口天花板。它连续重置，而不是在某个边界重置：早于窗口的支出会掉出尾随合计，因此没有按月的悬崖，
  也没有午夜清零。它是门上的一个钩子，而不是一项独立能力，
  所以没有地址，也没有页面；上限本身是运营者编辑的
  平台标志。

## 归零时会发生什么

按量调用会被拒绝。它在工作发生之前就在门上被拒绝，
因此你永远不会为一次本将失败的调用付费——而且拒绝
会指出原因，而不是返回一个笼统错误，这样客户端不必猜测就能区分
「积分用尽」和「密钥错误」。不花钱的读取仍然
应答：你始终可以查看一笔花不出去的余额。

## 哪些调用要花钱

大多数不用。一项能力在代码旁边声明自己的价格——免费、固定，或
按量——免费的占多数：列出项目、读取
webhook 的投递、获取自己的资料。按量计费的是
消耗真实资源的东西——推理词元、沙箱秒数、一条出站短信、
一个被抓取的页面。

每个能力页面都给出自己的答案，[定价](/docs/pricing)
承载每个模型与工具的费率表。
