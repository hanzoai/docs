There are 500+ models behind one key and one address. That number is large enough to be useless as a guide, so here is the guide: pass the `id` as `model`, and the rest of the request is the same whichever you pick. Choosing is a question of price, context, and whether the model is good at your particular job. The request itself does not change, which means you can answer the choosing question with an experiment instead of a commitment.

```bash
curl https://api.hanzo.ai/v1/chat/completions \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"<id from below>","messages":[{"role":"user","content":"Hello"}]}'
```

The table is fetched from [`/v1/models`](/docs/openapi/ai) in your browser when this page loads. It is the catalogue the gateway is serving right now, not a copy someone typed when the page was built. If a blog post, a slide, or an old tab disagrees with the table, the table is the one having a better day.

## What a rate means

Rates are per million tokens, input and output priced separately. They are the same whether you call from the CLI, an SDK, HTTP, or an MCP tool — the price is a property of the model, not of the door you walked in through. Routing does not add a percentage on top. When a request is routed, you pay the fixed per-token price of the model that served it.

[Pricing](/docs/pricing) is how usage becomes a bill. [Credits](/docs/credits) is what happens when the balance runs out, which is a different surprise and worth meeting in advance.
