`hanzo code` 针对你正站着的仓库运行一个编程智能体。
支持三个智能体，点名其中一个就得到它，或者得到一次明确的失败 —
它们是各自的产品，从不是彼此的别名。

```bash
hanzo code                      # Hanzo Dev, the default
hanzo code claude               # Claude Code
hanzo code codex                # Codex
```

把任务作为 **一个** 参数传进去，加上引号：

```bash
hanzo code "fix the failing test in api/users"
hanzo code claude "port this module to the new store"
```

## 点名智能体

下面每一种写法都在同一处解析，所以不会各走各的：

| | 位置参数 | 标志 | 显式 |
| --- | --- | --- | --- |
| Hanzo Dev | `hanzo code dev` | `hanzo code --dev` | `hanzo code --backend dev` |
| Claude Code | `hanzo code claude` | `hanzo code --claude` | `hanzo code --backend claude` |
| Codex | `hanzo code codex` | `hanzo code --codex` | `hanzo code --backend codex` |

`hanzo dev` 是 `hanzo code dev` 的顶层简写。`claude-code` 和
`cc` 是 `claude` 接受的写法。

点名两次会被拒绝，而不是被消解 — `hanzo code claude --codex`
会告诉你只点一次名。

## 批准

智能体默认自动批准自己的步骤。两条出路，按放弃的程度递增：

```bash
hanzo code --ask            # the backend asks before each step
hanzo code --no-sandbox     # bypass approvals AND drop the sandbox
```

`--safe` 是 `--ask` 的同义词，二者都会盖过 `~/.hanzo/settings.json` 里的
`autoApprove`。

## 另一个 `hanzo code`

`hanzo code context`、`hanzo code file` 和 `hanzo code index` 是共用这个词的另一件事：它们是 [代码智能 API](/docs/openapi/code) — 在已索引的仓库里搜索和查看符号，
给你用，也给智能体用。它们不接收后端，也不运行智能体。

规则是第一个参数：一个点出后端名字的词就选定它，
其他任何内容都是任务或子命令。
