## Cada modelo, una sola clave

<ProviderStrip />

Recorre [cada modelo que servimos](/docs/openapi/ai) — el catálogo está en vivo, así que el id que
copias y la tarifa junto a él son la respuesta actual de la pasarela — o mira [cuánto
cuesta una petición](/docs/pricing) antes de enviarla.

## La plataforma, por dominio

Cada capacidad tiene un nombre y una ruta — `/v1/<name>` — y vive en exactamente
un dominio. Nada está duplicado, así que nada es ambiguo.

## Llévatela contigo

La nube de arriba y la que puedes ejecutar tú son [el mismo
software](/docs/network) — el mismo binario, el mismo contrato, las mismas rutas `/v1`. Trae
tu propia GPU o Kubernetes, o mina en cualquier dispositivo.

```bash
curl -fsSL https://hanzo.sh | sh
```

<Callout type="info">
Esto es **V8 · Open Edition**, especificado en [HIP-0127](https://hips.hanzo.ai):
un contrato, muchos enlaces, clientes delgados y un cable — nunca FFI — entre
lenguajes. Mira [Filosofía de ingeniería](/docs/architecture/philosophy) para el *porqué*.
</Callout>

## Constrúyelo

- [La CLI `hanzo`](/docs/openapi/platform) — un binario Rust de unos 15 MB que habla con cualquier nube en vivo: producción, portátil o autoalojada
- [SDKs](/docs/sdks) — Python, TypeScript, Go, Rust y más, todos derivados de un solo contrato
- [Referencia de API](/docs/openapi) — cada endpoint, generado desde su especificación
- [Protocolo ZAP](/docs/zap) — Zero-Copy App Proto, el cable que hablan las mitades Go y Rust
- [Modelos Zen](https://zenlm.org) — modelos abiertos de frontera, del borde de 4B al razonamiento de 1T+
- [Arquitectura](/docs/architecture) — un binario, un contrato, y el porqué
