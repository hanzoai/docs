---
title: Skills
description: Teach Hanzo Dev reusable procedures with SKILL.md files.
---

A skill is a folder with a `SKILL.md` file: a name, a description of when to use it, and instructions. Hanzo Dev lists your skills to the model, which loads one when the task matches its description.

## Write a skill

```markdown title=".agents/skills/release-notes/SKILL.md"
---
name: release-notes
description: Draft release notes from the commits since the last tag. Use when asked for release notes or a changelog entry.
---

1. Find the last tag with `git describe --tags --abbrev=0`.
2. Summarize `git log <tag>..HEAD` by user-visible change.
3. ...
```

| Field | Rule |
| --- | --- |
| `name` | At most 64 characters. Defaults to the folder name. |
| `description` | Required and non-empty. This is what the model reads to decide when to use the skill, so say what it does and when. |

Keep scripts, references and examples next to `SKILL.md` in the same folder.

## Where skills live

| Location | Scope |
| --- | --- |
| `.agents/skills/<name>/SKILL.md` in the repository — in any directory from the root down to where you started | This repository |
| `~/.agents/skills/<name>/SKILL.md` | Every repository |

Hanzo Dev also ships a few built-in skills.

## Use a skill

Mention it with `$` in the composer — `$release-notes` — or browse them with `/skills`. The model can also pick one on its own from its description.

## Turn skills off

Disable one skill in `config.toml`:

```toml
[[skills.config]]
name = "release-notes"
enabled = false
```

Turn off the built-in skills:

```toml
[skills.bundled]
enabled = false
```
