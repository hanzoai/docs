---
title: Subagents
description: Let Hanzo Dev delegate work to subagents, and define your own agent roles.
---

Hanzo Dev can spawn subagents: separate agent threads it hands a piece of the task to, runs in parallel, and collects results from. Ask for it in plain words — "explore how auth works and, in parallel, find every caller of `parseToken`" — and the model decides when to delegate.

## Watch and switch

| Where | How |
| --- | --- |
| Inside a session | `/subagents` switches between this session's subagents. |
| Inside a session | `/agents` shows every active session. |
| From the shell | `dev agents` opens the same overview. |

## Built-in roles

| Role | Use |
| --- | --- |
| `default` | A general agent. |
| `explorer` | Fast, well-scoped questions about the codebase. |
| `worker` | Execution and production work. |

## Define a role

Declare a role in `config.toml` and give it its own configuration file:

```toml title="~/.hanzo/dev/config.toml"
[agents.reviewer]
description = "Reviews a diff for correctness and security issues. Read-only."
config_file = "./agents/reviewer.toml"
```

```toml title="~/.hanzo/dev/agents/reviewer.toml"
model = "enso"
sandbox_mode = "read-only"
developer_instructions = "Report findings with file and line. Do not edit files."
```

`description` is what the model reads when choosing a role. `config_file` is a [configuration](/docs/dev/configuration) layer applied to agents of that role; a relative path is resolved from the `config.toml` that names it.

## Settings

```toml
[agents]
enabled = true                          # subagents on (default)
max_concurrent_threads_per_session = 4  # open subagents per session
default_subagent_model = "enso"         # when a spawn does not pick one
default_subagent_reasoning_effort = "medium"
```

Set `enabled = false` to turn subagents off.
