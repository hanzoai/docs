## Diagnose the installation

```bash
dev doctor
```

`dev doctor` checks the installation, configuration, sign-in, terminal, Git, sandbox, MCP servers and network reachability. Every row is ok, warning or fail, with a fix for each failure. It changes nothing, and exits `1` when a check fails.

| Option | Effect |
| --- | --- |
| `--summary` | Only the grouped rows and the final count. |
| `--all` | Expand long lists. |
| `--json` | A redacted, machine-readable report. |

## See where a setting came from

Inside a session, `/debug-config` shows each configuration layer and what it set. `/status` shows the session's model, sandbox, approval policy and token usage.

## Write a log file

Set `log_dir` in `config.toml`, and the interactive session writes `codex-tui.log` there:

```toml title="~/.hanzo/dev/config.toml"
log_dir = "/home/me/dev-logs"
```

```bash
tail -F /home/me/dev-logs/codex-tui.log
```

Choose a directory of your own: a log file in `~/.hanzo/dev/log/` is removed every time a session starts. Set `RUST_LOG` to change what is logged, e.g. `RUST_LOG=debug dev`.

`dev exec` prints errors to stderr; `RUST_LOG` raises its level too.

## Send logs to the maintainers

`/feedback` inside a session sends its logs.
