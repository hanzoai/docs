---
title: Headless Runs and CI
description: Run Hanzo Dev to completion without the interface with dev exec, and review changes with dev review.
---

`dev exec` runs one task to completion and exits. It never stops to ask for approval: a command the sandbox refuses fails back to the model.

```bash
dev exec "add error handling to main.py"
```

If you give no prompt, or `-`, the prompt is read from stdin. If you pipe stdin and also give a prompt, stdin is appended to the prompt as a `<stdin>` block:

```bash
git diff | dev exec "write a commit message for this diff"
```

## Let it edit files

`dev exec` uses the sandbox mode your [configuration](/docs/dev/configuration/sandbox#sandbox-modes) resolves to, which is `read-only` unless the directory is trusted or you have set `sandbox_mode`. Give a run write access to the workspace with `-s`:

```bash
dev exec -s workspace-write "fix all lint errors"
```

See [Sandbox and approvals](/docs/dev/configuration/sandbox).

## Outside a Git repository

`dev exec` refuses to run outside a Git repository unless you pass `--skip-git-repo-check`.

## Output

| Flag | Effect |
| --- | --- |
| `--json` | Print every event to stdout as JSON lines. |
| `-o, --output-last-message <FILE>` | Write the agent's final message to a file. |
| `--output-schema <FILE>` | Require the final message to match a JSON Schema. |
| `--color always\|never\|auto` | Color for human-readable output (default `auto`). |
| `--ephemeral` | Do not save the session to disk. |

```bash
dev exec --output-schema schema.json -o result.json "list the public functions in src/"
```

## Exit status

`dev exec` exits `0` on success and `1` on any error — a bad `-c` override, a configuration error, a missing prompt, or an error during the run.

## CI

```yaml
- name: Update the changelog
  run: |
    npm install -g @hanzo/dev
    dev exec -s workspace-write "update CHANGELOG.md for the next release"
  env:
    HANZO_USER_KEY: ${{ secrets.HANZO_USER_KEY }}
```

## Continue a headless run

```bash
dev exec resume --last "now add tests for it"
dev exec resume 7f9f9a2e-1b3c-4c7a-9b0e-123456789abc "now add tests for it"
```

The session is named by its id or name. With `--last`, a single argument is the prompt.

## Review changes

`dev review` reviews the repository's changes and prints the findings:

```bash
dev review --uncommitted
dev review --base main
dev review --commit 1a2b3c4
dev review "focus on error handling"
```

| Option | Reviews |
| --- | --- |
| `--uncommitted` | Staged, unstaged and untracked changes. |
| `--base <BRANCH>` | Changes against a base branch. |
| `--commit <SHA>` | The changes one commit introduced (`--title` labels it). |
| `[PROMPT]` | Your own review instructions (`-` reads them from stdin). |

Choose one of the four.
