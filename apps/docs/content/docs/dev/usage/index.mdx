Run `dev` in a repository to open a session. Give the first task on the command line to start straight away:

```bash
dev "add input validation to the signup handler"
```

## In the composer

| Type | What happens |
| --- | --- |
| A message, then **Enter** | Sends it. |
| **Tab** while a turn is running | Queues the message for when the turn ends. |
| `@` | Mentions a file, skill or plugin. |
| `$` | Mentions a skill or app. |
| `!` followed by a command | Runs that shell command yourself. |
| `/` | Opens the [slash commands](/docs/dev/usage/slash-commands). |
| A path to an image file | Attaches the image. |

To attach images at launch, pass `-i`:

```bash
dev -i screenshot.png "what's wrong with this layout?"
```

## Keys

| Key | Action |
| --- | --- |
| **Esc** | Interrupt the running turn. |
| **Esc** twice | Pick an earlier message of yours; **Enter** forks the conversation before it so you can edit and resend. |
| **Up** / **Down** | Recall earlier messages. |
| **Ctrl+R** | Search message history. |
| **Alt+,** / **Alt+.** | Lower / raise reasoning effort. |
| **Ctrl+T** | Open the transcript. |
| **Ctrl+G** | Edit the message in your external editor. |
| **Ctrl+L** | Clear the terminal. |
| **Shift+Enter** | Insert a newline. |
| **?** | Show all shortcuts. |

Remap any of them with `/keymap`.

## Project instructions: AGENTS.md

Run `/init` and Hanzo Dev writes an `AGENTS.md` describing the repository. Edit it: it is read at the start of every session, so it is where conventions, architecture notes and "do not touch" rules belong.

Hanzo Dev reads, in order:

1. `~/.hanzo/dev/AGENTS.md` — your own instructions for every project.
2. `AGENTS.md` in each directory from the repository root down to the directory you started in.

Together they are limited to 32 KiB (`project_doc_max_bytes`); anything beyond is cut off. Project files are read only in a [trusted](/docs/dev/configuration#trust) directory.

## Choose a model

Pick a model and reasoning effort with `/model`, or start with one:

```bash
dev -m enso
```

Model ids come from the Hanzo gateway, which is the only authority on the catalog.

## Run several sessions

Sessions are saved as you work. [Sessions](/docs/dev/usage/sessions) covers resuming, forking and switching between them.
