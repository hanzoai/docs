Hanzo Dev reads its settings from `~/.hanzo/dev/config.toml`. The first run creates it:

```toml title="~/.hanzo/dev/config.toml"
model_provider = "hanzo"
model = "enso-auto"

[model_providers.hanzo]
name = "Hanzo"
base_url = "https://api.hanzo.ai/v1"
wire_api = "responses"
env_key = "HANZO_USER_KEY"
env_key_instructions = "Run `dev login` to sign in to Hanzo or paste a Hanzo API key, or set HANZO_USER_KEY."
requires_openai_auth = false

[mcp_servers.hanzo]
command = "hanzo-mcp"
args = []
```

Everything Hanzo Dev keeps — configuration, credentials, sessions, skills, rules — is in this home directory. Set `DEV_HOME` to use another one; it then keeps its own credentials too.

See [Example configuration](/docs/dev/configuration/example-config) for a fuller file.

## Layers

Settings combine from several layers. A higher layer overrides a lower one, key by key:

1. **Command-line flags and `-c` overrides** for this run.
2. **The project's `.codex/config.toml`** — in the repository root, or in any directory between it and where you started. Read only when the directory is [trusted](#trust).
3. **A profile** chosen with `--profile`.
4. **Your `~/.hanzo/dev/config.toml`.**
5. **The system's `/etc/codex/config.toml`.**

A project's `.codex/config.toml` cannot set `model_provider`, `model_providers`, `notify`, `profiles`, `otel` or `chatgpt_base_url`; those are ignored there.

`/debug-config` inside a session shows every layer and what it set.

## Override one setting for a run

```bash
dev -c model=enso
dev -c shell_environment_policy.inherit=core
dev -c 'sandbox_workspace_write.writable_roots=["/tmp/build"]'
```

The key is a dotted path. The value is parsed as TOML; if it is not valid TOML it is taken as a string, so `-c model=enso` and `-c model='"enso"'` are the same. `-c` can be repeated and works after any subcommand.

## Profiles

A profile is a second file layered over your config:

```toml title="~/.hanzo/dev/work.config.toml"
model = "zen5-coder"
model_reasoning_effort = "high"
```

```bash
dev --profile work
```

`--profile <name>` reads `~/.hanzo/dev/<name>.config.toml`. Names use letters, digits, `_` and `-`.

## Trust

The first time you open a directory, Hanzo Dev asks whether you trust it, and records the answer:

```toml
[projects."/home/me/src/app"]
trust_level = "trusted"   # or "untrusted"
```

In a trusted directory the project's `.codex/config.toml`, `AGENTS.md` files, hooks and [command rules](/docs/dev/usage/execpolicy) load, and the sandbox defaults to `workspace-write`. An untrusted directory gets none of the project's own files.

## Model

```toml
model = "enso-auto"
model_reasoning_effort = "medium"   # none | minimal | low | medium | high | xhigh
model_reasoning_summary = "auto"    # auto | concise | detailed | none
model_verbosity = "medium"          # low | medium | high
review_model = "enso"               # model for /review and dev review
```

Model ids come from the Hanzo gateway; browse them with `curl https://catalog.hanzo.ai/v1/models`. Which reasoning efforts a model accepts is up to the model.

## Model providers

The Hanzo provider is set up for you. To add another, declare it and select it:

```toml
model_provider = "azure"

[model_providers.azure]
name = "Azure"
base_url = "https://YOUR_PROJECT.openai.azure.com/openai"
env_key = "AZURE_OPENAI_API_KEY"
query_params = { api-version = "2025-04-01-preview" }
```

| Key | Meaning |
| --- | --- |
| `name` | Display name (required). |
| `base_url` | The API's base URL. It must speak the Responses API. |
| `env_key` | Environment variable holding the API key. |
| `query_params` | Extra query parameters on every request. |
| `http_headers` / `env_http_headers` | Fixed headers / headers read from environment variables. |
| `request_max_retries` | Retries for a failed request (default `4`). |
| `stream_max_retries` | Retries for a dropped stream (default `5`). |
| `stream_idle_timeout_ms` | How long a stream may stay silent (default `300000`). |

`openai`, `ollama` and `lmstudio` are built in and cannot be redefined. To use a local model, run Ollama or LM Studio and pass `--oss`:

```bash
dev --oss --local-provider ollama -m llama3
```

## Sandbox and approvals

```toml
sandbox_mode = "workspace-write"    # read-only | workspace-write | danger-full-access
approval_policy = "on-request"      # on-request | never
```

See [Sandbox and approvals](/docs/dev/configuration/sandbox).

## Environment of the commands the agent runs

```toml
[shell_environment_policy]
inherit = "core"                    # all (default) | core | none
exclude = ["AWS_*", "*_TOKEN"]
set = { CI = "1" }
include_only = []                   # when non-empty, keep only these
```

The agent's commands start from `inherit`: every variable (`all`), only `PATH`, `SHELL`, `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TMPDIR`, `TEMP` and `TMP` (`core`; Windows has its own set), or nothing (`none`). Then `exclude` removes matching variables, `set` adds yours, and a non-empty `include_only` keeps only what matches. Patterns use `*` and `?` and ignore case.

## Instructions

```toml
developer_instructions = "Prefer small, reviewable commits."
project_doc_max_bytes = 32768       # AGENTS.md budget, default 32 KiB
```

`developer_instructions` is added to every session. Project instructions belong in `AGENTS.md`; see [Project instructions](/docs/dev/usage#project-instructions-agentsmd).

## Web search

```toml
web_search = "live"                 # disabled | cached (default) | indexed | live
```

`dev --search` turns on live search for one session.

## Interface

```toml
file_opener = "vscode"              # vscode | vscode-insiders | windsurf | cursor | none
hide_agent_reasoning = false
notify = ["notify-send", "Hanzo Dev"]   # run with a JSON event when a turn completes

[tui]
notifications = true                # terminal notifications
animations = true
alternate_screen = "auto"           # auto | always | never

[history]
persistence = "save-all"            # save-all | none
```

## Features

Optional and experimental behaviour is behind feature flags:

```bash
dev features list               # every feature, its stage, on or off
dev features enable worktrees
dev features disable memories
```

`enable` and `disable` write to the `[features]` table of `config.toml`:

```toml
[features]
worktrees = true
```

Inside a session, `/experimental` toggles them.

## Telemetry

Log and trace export is off (`none`) until you configure an exporter:

```toml
[otel]
environment = "dev"
log_user_prompt = false

[otel.exporter.otlp-http]
endpoint = "https://otel.example.com/v1/logs"
protocol = "binary"                 # binary | json
```

## Unknown keys

Run `dev --strict-config` to fail on any key this version does not recognize, instead of ignoring it.
