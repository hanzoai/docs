## Which models can I use?

Any model the Hanzo gateway serves. The default is `enso-auto`; pick another with `/model` or `dev -m <model>`. Browse the catalog with `curl https://catalog.hanzo.ai/v1/models`.

## How do I stop it from editing my files?

Run read-only:

```bash
dev -s read-only
```

or set `sandbox_mode = "read-only"` in `config.toml`. See [Sandbox and approvals](/docs/dev/configuration/sandbox).

## Does it work on Windows?

Yes, natively on Windows x64. Set `[windows] sandbox = "elevated"` and run `/setup-default-sandbox` once so the agent can write inside the workspace; until then it runs read-only. See [Platform sandboxing](/docs/dev/configuration/platform-sandboxing#windows).

## Where does it keep its files?

In `~/.hanzo/dev`, or the directory `DEV_HOME` names: `config.toml`, credentials, `sessions/`, `history.jsonl`, `rules/`, and `kai.toml` if you create one.

## Why doesn't it read my project's `.codex/config.toml` or `AGENTS.md`?

The directory is not trusted. See [Trust](/docs/dev/configuration#trust).

## Does my usage go through Hanzo?

With the Hanzo provider, model calls go to `api.hanzo.ai` and are metered on your Hanzo account. Signing in with ChatGPT or an OpenAI key switches the provider to OpenAI.

## Where does Hanzo Dev come from?

It is built from [github.com/hanzoai/dev](https://github.com/hanzoai/dev), Apache-2.0. It is a fork of open-source coding agents; the repository's `NOTICE` lists them.
