## Every model, one key

<ProviderStrip />

The catalogue is not a brochure we typed in and then forgot. [Every model we serve](/docs/openapi/ai) is the gateway's current answer — the id you copy and the rate beside it are live — and [what a request costs](/docs/pricing) is worth a look before you send a large one. There are 500+ models. You do not need to pick one before you understand the shape of a call, which is the same for all of them.

## The platform, by domain

A platform with this many names can feel like a city with no street signs. The signs are simpler than the list. Every capability has one name and one route, `/v1/<name>`, and it lives in exactly one domain. Nothing is listed twice, which is how you know you have found the right door.

## Take it with you

Here is a fact that surprises people, and it is worth sitting with. The cloud above and the one you can run yourself are [the same software](/docs/network) — same binary, same contract, same `/v1` routes. Bring your own GPU or Kubernetes, or mine on any device. There is no smaller edition hiding a smaller API.

```bash
curl -fsSL https://hanzo.sh | sh
```

<Callout type="info">
This is **V8 · Open Edition**, specified in [HIP-0127](https://hips.hanzo.ai):
one contract, many bindings, thin clients, and a wire — never FFI — between
languages. [Engineering Philosophy](/docs/architecture/philosophy) is the *why*, told with a little less formality than the proposal.
</Callout>

## Build with it

- [The `hanzo` CLI](/docs/openapi/platform) — one ~15 MB Rust binary that talks to any live cloud: prod, laptop, or self-host
- [SDKs](/docs/sdks) — Python, TypeScript, Go, Rust and more, all derived from one contract
- [API reference](/docs/openapi) — every endpoint, generated from its spec
- [ZAP protocol](/docs/zap) — Zero-Copy App Proto, the wire the Go and Rust halves speak
- [Zen models](https://zenlm.org) — open-weight models, from a 4B model at the edge to 1T+ reasoning
- [Architecture](/docs/architecture) — one binary, one contract, and why we were willing to be stubborn about both
