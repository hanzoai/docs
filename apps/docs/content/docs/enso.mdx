# Meet enso

Enso is Hanzo's small language model, and it also routes. You talk to it the way you talk to any other model on the gateway: one endpoint, one key, one request shape. The only thing you change is the `model` string.

Each tier is a different trade of effort, speed, and intelligence, at a fixed price per million tokens. Name a tier when you know which trade you want. Name `enso` when you want the gateway to choose. A request that names no tier is billed at the `enso-flash` rate. If nothing pays for the tier that would have answered, the request is served by `enso-free`, at no charge.

Hanzo's own models, including Enso, carry only a payment processing fee: 3.5% by credit card, or 3% in crypto. There is no routing fee on them. Third-party models follow [OpenRouter](https://openrouter.ai/pricing). On the standard plan that is 5.5% by credit card, or 5% in crypto. The Business plan is 8% on credit purchases. Enterprise fees are not published; contact sales. Bring-your-own-key includes $25,000 of list-price inference a month with no fee, then 5%.

`enso-auto` and `hanzo/enso` are spellings of `enso`, not extra models.

## See them for yourself

The model catalog is what the gateway answers from, and reading it needs no key
— you can run this line right now, before you have one:

```bash
curl -s https://api.hanzo.ai/v1/models \
  | jq '.data[] | select(.id | startswith("enso"))'
```

Each entry carries the `id` you pass as `model`, `owned_by`, `context_window`, and `pricing.input_per_million` / `pricing.output_per_million`. Per-token rates, if you need them, are `pricing.prompt` and `pricing.completion`. If this page and that command ever disagree, believe the command. [Pricing](/docs/pricing) is generated from the gateway rather than typed by hand.

## Which one

<Callout title="Start on the cheaper rate.">
`enso` and `enso-flash` are $0.33 in and $1.65 out per million tokens. `enso-pro` and `enso-ultra` cost more because they spend more effort. Move up when the cheaper tier has disappointed you on a prompt you care about. Switching is one word in the request.
</Callout>

Token prices below are the billing rates for each tier. Context windows are `data[].context_window` from `GET /v1/models`, read on 29 October 2026. Per-million prices on that response are `pricing.input_per_million` and `pricing.output_per_million`.

| Model | Context | In / Out (per 1M tokens) | Reach for it when |
|---|---|---|---|
| `enso-free` | 1,000,000 | $0 / $0 | Nothing is paying for the request. |
| `enso-flash` | 900,000 | $0.33 / $1.65 | Cheaper and faster, for everyday work. |
| `enso` | 900,000 | $0.33 / $1.65 | The router. A request that names no tier is billed here. |
| `enso-pro` | 1,000,000 | $4.40 / $22 | More effort and intelligence than flash. |
| `enso-ultra` | 1,000,000 | $5.50 / $27.50 | The most effort, for the hardest work. |

`enso-auto` and `hanzo/enso` return the same description, context, and price as `enso`. They are spellings of the router, not extra models.

The columns are **cost**, not speed. A cheaper tier is not a promise of a faster answer. The next section is how to measure that yourself.

## Measure them yourself

Do not take anyone's word for which tier is fast — including this page's. Send
one prompt to all three and time it. This is the whole experiment:

```bash
for m in enso enso-flash enso-ultra; do
  printf '%-11s ' "$m"
  curl -s -o /dev/null -w '%{http_code}  %{time_total}s\n' \
    https://api.hanzo.ai/v1/chat/completions \
    -H "Authorization: Bearer $HANZO_API_KEY" \
    -H 'Content-Type: application/json' \
    -d "{\"model\":\"$m\",\"messages\":[{\"role\":\"user\",\"content\":\"In two sentences, explain what an API key is to someone who has never used one.\"}]}"
done
```

`-o /dev/null` throws the answer away and `-w` prints only the status code and
the wall-clock time, so you are timing the request and nothing else. One run:

```
enso        200  18.481812s
enso-flash  200  9.737156s
enso-ultra  200  4.755649s
```

Run it a few times and the spread matters more than any single number. Over five
rounds of that same prompt:

| Model | Fastest | Median | Slowest |
|---|---|---|---|
| `enso-ultra` | 4.49s | **4.85s** | 5.21s |
| `enso-flash` | 8.21s | **14.91s** | 33.13s |
| `enso` | 19.15s | **20.26s** | 20.69s |

Two things there are worth internalising, because neither is what the names
imply. **`enso-ultra` was the fastest of the three on this prompt**, not the
slowest — consistent with its design: it sizes a model to the task, and an easy
question never reaches the panel. And **`enso-flash` was the least consistent** —
its slowest round was four times its fastest, so a single timing tells you very
little about the next one.

Take that as a method, not as a league table. The prompt above is an easy one, and these numbers describe that prompt at that time. A different prompt can reorder them. The loop does not include `enso-pro` or `enso-free`; add them when those are the tiers you intend to use. Time the ids on the kind of question you actually plan to ask, and re-time them when that changes.

## What an answer looks like

Same prompt, sent to `enso-ultra`, printed exactly as it came back:

> An API key is a unique string of characters that acts like a password,
> allowing a program to access a specific service or application programming
> interface (API). It identifies the user or application to the service,
> ensuring that only authorized users can make requests and helping track usage
> for billing or rate-limiting purposes.

That request billed 275 input tokens and 70 output tokens — the `usage` object in the response says so. At ultra's $5.50 / $27.50 per million that is about **$0.0034**. The same traffic through `enso-flash`, at $0.33 / $1.65, is about **$0.0002**. Read `usage` rather than estimating: it is the number you are actually charged for.

## Switching between them

One string. Everything else about the request is identical.

<Tabs items={['curl', 'Python', 'TypeScript']}>

<Tab value="curl">

```bash
curl https://api.hanzo.ai/v1/chat/completions \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "enso-flash",
    "messages": [{ "role": "user", "content": "Name three uses for a paperclip." }]
  }'
```

</Tab>

<Tab value="Python">

```python
import os
from hanzoai import Hanzo

client = Hanzo(api_key=os.environ["HANZO_API_KEY"])

answer = client.chat.completions.create(
    model="enso-flash",                      # or "enso", "enso-pro", "enso-ultra"
    messages=[{"role": "user", "content": "Name three uses for a paperclip."}],
)
print(answer.choices[0].message.content)
```

</Tab>

<Tab value="TypeScript">

```typescript
import Hanzo from '@hanzo/ai';

const client = new Hanzo({ apiKey: process.env.HANZO_API_KEY });

const answer = await client.chat.completions.create({
  model: 'enso-flash',                       // or 'enso', 'enso-pro', 'enso-ultra'
  messages: [{ role: 'user', content: 'Name three uses for a paperclip.' }],
});
console.log(answer.choices[0].message.content);
```

</Tab>

</Tabs>

That is the whole change between tiers. Start on the cheaper rate — `enso` or `enso-flash` — and move up when that tier has failed the prompt you care about. Every model in the catalogue answers on that same path.

### If you already have an HTTP client

`/v1/chat/completions` takes and returns the same JSON shapes as the
widely-implemented chat-completions format — an interchange format we do not own
and had no reason to re-invent. A client written against it works here once its
base URL points at `https://api.hanzo.ai/v1` and it sends a Hanzo key. The ids
do not travel, though: `enso` is ours and resolves only here.

## What a request costs

Prices are per million tokens, so divide. A 2,000-token prompt with a 500-token
answer:

| Model | Input | Output | Total |
|---|---|---|---|
| `enso-free` | 2,000 x $0/1M = $0 | 500 x $0/1M = $0 | **$0** |
| `enso-flash`, `enso` | 2,000 x $0.33/1M = $0.00066 | 500 x $1.65/1M = $0.000825 | **$0.001485** |
| `enso-pro` | 2,000 x $4.40/1M = $0.0088 | 500 x $22/1M = $0.011 | **$0.0198** |
| `enso-ultra` | 2,000 x $5.50/1M = $0.011 | 500 x $27.50/1M = $0.01375 | **$0.02475** |

A token is roughly three quarters of a word, so "2,000 tokens" is about three
pages. The response you get back reports exactly what you were charged for in
its `usage` field — trust that over any estimate, including this one.
