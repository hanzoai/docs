You should leave this page with two ordinary things: a credential that works, and one call that came back with an answer. That is the whole goal. Everything else on the page is in service of those two.

Hanzo is a cloud with a lot of parts — models, identity, storage, money, agents — and they all answer at `https://api.hanzo.ai`. The CLI, the SDKs, and the MCP tools are generated from one description of that cloud, which is why you do not wire each service up by hand. Get a key once. The rest is reachable from it.

People often skip the first real call and then wonder, an hour later, whether the key was the problem. Do the call. It is the cheapest experiment on this page.

## 1. Install

Four ways in, because people arrive with different tools already on the machine. They install the same `hanzo` program. Pick the one that matches what you already use.

<Tabs items={['npm', 'Script', 'Homebrew', 'From source']}>
<Tab value="npm">
```bash
npm i -g hanzo
```

`hanzo` is the CLI and the client in one install.
</Tab>
<Tab value="Script">
```bash
curl -fsSL https://hanzo.sh | sh
```

Installs into `~/.local/bin`. `https://hanzo.sh/cli` installs the CLI alone.
</Tab>
<Tab value="Homebrew">
```bash
brew install hanzoai/tap/hanzo
```
</Tab>
<Tab value="From source">
```bash
git clone https://github.com/hanzoai/cli && cd cli && cargo install --path .
```
</Tab>
</Tabs>

```bash
hanzo version
```

## 2. Log in

A person and a server log in differently, and mixing them up is the first real mistake available to you. Get this one right and a lot of later confusion does not happen.

```bash
hanzo auth login
```

That opens a browser against [hanzo.id](https://hanzo.id), Hanzo's identity
provider, and stores the resulting credential locally. `hanzo auth show` prints
who you are; `hanzo auth list` shows every identity on this machine and
`hanzo auth use` switches between them.

For a server, mint a key instead of logging a person in: **console.hanzo.ai →
API keys**. A secret key resolves to *you*, so it belongs on a server and never
in a browser — [Authentication](/docs/api-keys) is the whole rule. The distinction feels fussy until a key leaks from a frontend, and then it feels obvious.

```bash
export HANZO_API_KEY=sk-...
```

## 3. List the models

This is the catalogue the gateway is serving right now. It is a read, it needs nothing but the key, and — this is the part worth noticing — it is the same operation whether you ask from the CLI, an SDK, raw HTTP, or an MCP tool. Four spellings, one question. If the four answers ever disagree, believe the HTTP one: that is the gateway itself.

Every one of these is generated from the same description of the API, so the
method names line up across languages. [C++](/docs/sdks/cpp) is the one still
landing.
</Tab>
<Tab value="HTTP">
```bash
curl https://api.hanzo.ai/v1/models \
  -H "Authorization: Bearer $HANZO_API_KEY"
```
</Tab>
<Tab value="MCP">
```bash
curl -X POST https://api.hanzo.ai/v1/mcp \
  -H "Authorization: Bearer $HANZO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

One endpoint, one tool per capability. `tools/call` names the capability and the
operation; `describe` explains any operation's input.
</Tab>
</Tabs>

Those four tabs are one API, seen from four chairs. The difference is spelling, not capability. Pick the chair you will actually sit in:

- **[CLI](/docs/cli)** — every capability as a command group, one page each.
- **[SDKs](/docs/sdks)** — Python, TypeScript, Go, Rust, C++, Swift and Kotlin,
  generated from the same description the CLI and the tools are.
- **[MCP](/docs/mcp)** — one endpoint an agent connects to; [the tools](/docs/mcp-tools)
  are listed one per capability.

HTTP needs no page of its own. It is `https://api.hanzo.ai` and the key you exported above.

## 4. Send a completion

This is the first step that spends anything. Everything above was free to run, which is why it was safe to experiment. From here, a call draws down credit.

```bash
hanzo chat completions --model zen-1 --messages '[{"role":"user","content":"hello"}]'
```

Then read what it drew down:

```bash
hanzo billing balance
hanzo usage summary
```

[Credits & billing](/docs/credits) explains what a credit is and what happens at
zero; [Pricing](/docs/pricing) is the rate for every model and tool.

## 5. Run the cloud locally

The same binary that serves `api.hanzo.ai` runs on your machine. That sentence is easy to read past. It means the laptop is not a toy version of the API. It is the API, with a shorter network cable.

```bash
hanzo up cloud
```

Bare `hanzo up` is the same thing — `cloud` is the default. Name one service to
run it alone: `hanzo up iam`, `hanzo up kms`, `hanzo up gateway`, `hanzo up
storage`, `hanzo up pubsub`. See [Run your own](/docs/network) for what that
means and what it needs.
